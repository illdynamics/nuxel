## The single remaining blocker (specific, now mechanical)

Provision item 360 to "internet" requires the EXACT on-disk QBR serialization of a u8[]
item inside nv_data.bin (length-prefix/framing + per-item offset). This is generated by
the CP's `cbd` QBR item-metadata table at runtime and was NOT recoverable from:
  - modem.bin / modem_debug.bin (descriptor table gives {type,name,id}, NOT offset/size)
  - libsec-ril.so (NvCoreInfo carries per-item SIZE, but the size list is populated at
    runtime from the CP; item 360's exact size is not statically present)
  - nv_data.bin (item 360 absent; "internet" absent; the file's TLV stream has no
    semantic ID markers for the APN)

Two concrete acquisition paths unlock it (neither invented, neither a blind write):
  (a) a known-good nv_data.bin from an IDENTICAL SM-G975F on KPN with the "internet"
      attach APN already present, as an authoritative byte reference, OR
  (b) tracing RFS_NV_WRITE_ITEM with item id 360 from the running vendor rild/cbd under
      an owner-approved redacted capture of the CP-bound NV write request (the CP returns
      the exact offset/size/framing it expects).
