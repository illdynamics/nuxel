The acceptance is stored locally, versioned, and required before anything can be queued. Bumping the notice version invalidates an old acceptance — accepting once does not authorise a future, different notice.

This app does not bypass DRM, paywalls or access controls, and Nuxel ships no third-party download service. Queueing a URL you have no right to is your problem, not a feature.

What actually happens

  • Who transfers: the Nuxel host (download.start over the bridge). A PWA cannot write files, so this page never claims to have written one itself. Host state: probing…
  • Queue persistence: the queue is stored in this app's local storage and survives a reload, an app switch and a reboot.
  • Resume: a paused item records the byte offset it reached and the host is asked to continue from there with a ranged request. If the server does not support ranges the item restarts and says so.
  • Retry: after three identical failures the strategy changes (direct → ranged resume → single-connection delayed retry) and, if that also fails, the item is blocked for a human decision instead of looping forever.
  • Verification: when an expected sha256 is supplied the host's digest must match before the item is marked done. A mismatch is a failure, never a warning.
  • Never contacted: …
  • No account: there is no sign-in, no API key and no cloud dashboard. Nothing in this app authenticates to a Google, Apple, Android or Meta service.

Where does the file go?

Downloads land in /home/nuxel/Downloads on the device, owned by the user that the host runs as. The VM smoke test exercises the queue, the notice gate and the refusal paths; it does not prove that a real network transfer happened anywhere.
