What NuxTore is

      
NuxTore is an offline-first local catalog: it lists the applications that are
        already staged inside this Nuxel image together with their content digests, provenance record and
        (for most packages) an Ed25519 signature. It has no upload code, no store account, no telemetry and no
        network fetch path, because the beta mission forbids external publishing and store submission.

    

    

      
How an install is gated

      
    
        
  • The bundle's file list must hash to the digest recorded in the catalog.
    • 
        
  • Every staged file is re-hashed from disk before the package is offered.
    • 
        
  • The signature must verify under a key that is present on the device.
    • 
        
  • A package that fails any check is listed under Refused / Blocked and cannot be installed.
    • 
        
  • Unsigned packages are refused by default. When the policy allows them, the operator must
          switch on unsigned installs and type the package id by hand — there is no auto-install path.
    • 
      

    

    

      
Signing keys — honest status

      
The beta catalog is signed by —. That key is a
        published development fixture: its private half is in this repository on purpose, so the
        offline verifier and its tests are reproducible. It is not a trust anchor, it protects
        nothing of value, and a production catalog must use a key whose private half never enters the
        repository. The beta build therefore claims signature integrity checking, not
        publisher trust.

    

    

      
Verify offline, independently

      
The authoritative check is a standard-library Python verifier that re-hashes every
        staged file and re-verifies every signature:

      
python3 pwa/nuxel-apps/nuxtore/tools/nuxtore-verify.py
python3 pwa/nuxel-apps/nuxtore/tests/test-catalog.py
python3 pwa/nuxel-apps/nuxtore/tools/nuxtore-stage.py --check
