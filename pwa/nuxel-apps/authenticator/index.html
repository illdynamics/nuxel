Create vault

Storage: AES-256-GCM under a PBKDF2-SHA-256 key. There is no account, no sync server and no network call anywhere in this app — the vault is a single encrypted file on this device.

Codes are computed locally from the secret with WebCrypto. The countdown is the real remaining time in this 30 s (or 60 s) step — not a decorative animation.

Paste an otpauth:// URI

Only otpauth://totp/ works. A HOTP (counter) URI is refused rather than silently treated as time-based. Examples live in samples/otpauth-examples.json.

Enter details by hand

Validation is strict on purpose: a secret that is not decodable base32, fewer than 10 bytes of entropy, an unsupported hash, or a nonsense period is refused instead of stored and producing wrong codes later.

Export

Exports the encrypted envelope only. There is no plaintext export button: a plaintext file is how secrets end up in a chat message or a screenshot.

Import

Replacing the vault needs its passphrase afterwards — importing does not unlock it, and a file containing plaintext accounts is refused.

What this app is

  • RFC 4226/6238 TOTP over WebCrypto — no third-party library, no CDN, no analytics.
  • Vault: —, AES-256-GCM with a fresh 12-byte IV on every save.
  • Storage: this app's local storage only. —
  • No network: the module contains no fetch, XMLHttpRequest or WebSocket call, and the offline test suite greps the source to prove it.

What this app is not

  • It cannot tell you whether a service accepted a code — it only knows the code matches this device's clock and this secret.
  • It does not protect you if the device itself is compromised while unlocked (root compromise is out of scope for every claim this build makes).
  • It does not back anything up. Lose the passphrase and the secrets are gone.
  • It does not do HOTP, push approval, or "remember this device" tokens.
