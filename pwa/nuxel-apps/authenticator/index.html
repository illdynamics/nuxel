Add a Microsoft work or school account

Standard TOTP only — third-party software OATH. This is not Microsoft Authenticator push approval, number matching, passwordless phone sign-in, device registration/PRT, Intune compliance or passkey attestation. Nuxel cannot and will not impersonate Microsoft protocols.

  1. On a trusted device, open your organization's Microsoft Entra Security info page (or the enrollment page IT gave you). Do not type your work password into Nuxel Authenticator.
  2. Add a sign-in method and choose the option that explicitly permits a third-party authenticator or software OATH token. The wording depends on your tenant policy.
  3. When Entra shows a QR code or setup key, scan it below or paste the standard otpauth://totp/ URI. Confirm issuer, account, algorithm, digits and period.
  4. Enter the current code into Microsoft's enrollment page. Nuxel cannot verify tenant acceptance; only Microsoft's page can.

If your organization disables third-party OATH, requires push/number matching, device registration or a phishing-resistant method, stop and contact IT. Standard TOTP is not phishing-resistant and may not satisfy a Conditional Access policy that requires a phishing-resistant method.

Official docs: learn.microsoft.com/entra/identity/authentication/concept-authentication-oath-tokens

Checking…

This stores this Authenticator vault's passphrase in the Nuxel system keyring. Authenticator can unlock automatically only while the keyring is unlocked. Anyone or any process that can use the unlocked keyring with this app's granted access may be able to unlock these TOTP secrets. Keep the keyring protected.

Removing the saved credential never deletes your TOTP accounts. Deleting this Authenticator vault is a separate destructive action below; it never deletes Nuxel Vault password items.

What this app is

  • RFC 4226/6238 TOTP over WebCrypto — no third-party library, no CDN, no analytics.
  • Vault: —, AES-256-GCM with a fresh 12-byte IV on every save.
  • Storage: this app's local storage only. —
  • No network: the module contains no fetch, XMLHttpRequest or WebSocket call, and the offline test suite greps the source to prove it.

What this app is not

  • It cannot tell you whether a service accepted a code — it only knows the code matches this device's clock and this secret.
  • It does not protect you if the device itself is compromised while unlocked (root compromise is out of scope for every claim this build makes).
  • It does not back anything up. Lose the passphrase and the secrets are gone.
  • It does not do HOTP, push approval, or "remember this device" tokens.
