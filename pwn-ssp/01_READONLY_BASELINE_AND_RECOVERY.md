# 01 — READ-ONLY LIVE RECONCILIATION AND BOOT/DT RECOVERY SEAL

DeepSeek-V4-Pro-Thinking: begin from MASTER 00 and carry all safety constraints. NO writes, firmware loading, power-cycle, reboot or flash in this stage. The past camera DT scare makes a fresh live baseline mandatory.

1. Inspect the **actual** Git checkout/worktrees, local report directory and any host backups. Find exact currently active branch/commit, unstaged changes, active kernel source, build manifest, patch-applied markers and the missing November 21 state-machine report. Compare snapshots to `pwn/ssp1..6` (the first is `ssp.md`) and never overwrite current work with older ZIP content.
2. Validate device access first with a non-invasive SSH/ADB command and determine **normal Nuxel boot** or TWRP mode. A historical IP or SSH identity is not proof of current connectivity. If unreachable, inspect existing logs and host artifacts; do not infer dead hardware.
3. Gather read-only `uname`, `/proc/version`, `/proc/cmdline`, kernel configuration/symbol evidence, selected DTBO index, bootreason, systemd status, `ls -l /dev/block/by-name`, partition sizes, current DTB/DTBO/BOOT/RECOVERY identity and **hashes**. Only read from verified *by-name* targets and never dump user data, EFS or personal storage. Determine whether the legacy mapping `sda12/13/14/15` is still exact; never assume it. Determine whether the reconciled native `nuxel_ssp_bringup_hw` is actually present and whether 0025/0026/0027 ever reached the deployed kernel.
4. Identify and independently verify two *distinctly accessible* known-good recovery copies (host and TWRP-accessible) of the exact running BOOT image. Store manifest+hashes outside the Git repo, with device, timestamp, partition mapping, image size, kernel symbols, command-line and embedded DT tail hash. Save validated DTB/DTBO dumps as immutable read-only *references*; never reflash them. Confirm full recovery route without activating it: working TWRP, intact network/ADB modes, accepted write method and precise rollback procedure.
5. Collect latest read-only SSP status: `/sys/class/sensors/ssp_sensor/{nuxel_hub_diag,sensor_state,enable}` when present; accel/gyro `raw_data`, `/dev/ttyBCM`/`/dev/bbd_sensor` node existence and permissions; service state, `dmesg`, relevant journal, PM, SPI runtime status and GPIO/IRQ diagnostics. Do **not** trigger writes to `nuxel_bringup`, `nuxel_stream`, `mcu_power`, `ESW:READY`, `BBD:PassThru` or download firmware in this stage.
6. Record the actual boot-loader-owned DT identity and BOOT donor embedded/appended DT and hash tail. Check that packaging can safely preserve it byte-for-byte. Do not use the old image SHA or a stale `nuxel-boot-known-good.img` as the rollback until matched against live hardware.

**Required deliverables:** `reports/SSP-20261122-LIVE-BASELINE.md`, `reports/SSP-BOOT-DT-IMMUTABILITY-MANIFEST.json`, `reports/SSP-ROLLBACK-READINESS.md`. Distinguish `DEVICE_VERIFIED` versus `ARCHIVE_ONLY`. Gate 01 PASS only when you can truthfully show Nuxel health, verified rollback artifacts and exact boot/DT mapping. Otherwise stop before any BOOT flash.
