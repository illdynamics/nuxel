# Nuxel SSP / BCM47752 — deep audit of `nuxel-feat-ssp.zip`

**Analysis date:** 2026-11-16 (Europe/Amsterdam). **Scope:** uploaded ZIP, not a connected handset. No device writes. This document separates directly reproduced archive evidence, claims in included reports, and hypotheses requiring live verification.

## Executive outcome

**PROGRESS IN ENGINEERING TOOLING; NO PROVED SENSOR RECOVERY.** The supplied branch contains three new areas of work absent in the earlier `nuxel-main (2).zip`: a robust native-downloader test/patch-verification path, a Bionic ELF closure audit, and an isolated-vendor-daemon sandbox scaffold. The newest report says the last hardware session on Nov 16 still had accelerometer and gyro `0,0,0`, SSP `enable=0`, `ssp_down=true`; a later SSH attempt timed out before it could establish live state. Do not present this state as a current real-time observation.

**No kernel rewrite or new firmware is justified yet:** kernel SSP/BBD driver, Samsung `lhd`, HALs and a reported embedded firmware patch already exist. We have no proof that replacement firmware matches the ROM/ASIC/board or that the incomplete native uploader obeys a full ACK/NACK/retransmission protocol. The immediate missing artifact is an exact matching Android system/Bionic/VNDK/APEX runtime, plus live access for a bounded trial.

## Exact current dependency gap

The 14 unique unresolved ELF dependencies are:

`android.frameworks.schedulerservice@1.0.so`, `libbase.so`, `libc++.so`, `libc.so`, `libcutils.so`, `libdl.so`, `libhardware.so`, `libhardware_legacy.so`, `libhidlbase.so`, `libhidltransport.so`, `liblog.so`, `libm.so`, `libutils.so`, `libz.so`.

Some can be in vendor, some system/VNDK, some APEX; their presence at an arbitrary path is insufficient. The Bionic vendor process must resolve **matching Android ABI, linker namespaces, VNDK and transitive libraries**. Android 11+ may generate `/linkerconfig`, while Android 9/10 use platform-specific `ld.config` files. The lhd ELF interpreter is `/system/bin/linker64`. Its eight direct needed libraries are listed in `reports/PWNAGE-SSP-RUNTIME-INVENTORY.md`.

**Important:** Public vendor manifest entries corroborate that beyond2lte includes `lhd`/sensorhub, but do not identify the exact matching Android system build for the recovered binaries. Do not automatically combine a newer generic Bionic runtime with them.

## Hardware/software chain and stage gate

```
physical BCM47752/LSM6DSO
  -> Exynos DT regulators / SPI / IRQ / GPIO / BBD protocol
  -> Samsung lhd UART/SSI + firmware patch downloader (requires Android runtime)
  -> kernel /dev/ttyBCM, /dev/bbd_sensor, /dev/bbd_control, /dev/bbd_patch
  -> SSP MCU bring-up and /sys/class/sensors/* real samples
  -> Nuxel orientation bridge/daemon
  -> compositor physical auto-rotation
```

The last proven failure is **before actual SSC/SSP sensor streaming**. A functioning Nuxel orientation service is not proof of a functioning sensor.

### Correct interpretation of embedded patch

Reported in `SENSORS-FIRST-LIGHT.md` from a live/on-disk source in prior work:
- ASIC `0x004775b0`
- decoded patch length 438,895 bytes
- address `0x00800161`
- patch export 897,113 bytes, SHA-256 `0b53f3b04bfb3d5c19727aac1e33e7a44693a2c01be37bfd1ea3b0ef4e859d72`
- decoded IEEE CRC-32 `0x93d35bb4`
- header `Crc=0xc1` is *not established* as IEEE CRC-32 and must not be equated with it.

The patch file is kernel-embedded and exposed via `/dev/bbd_patch`; do not pull a differently named Broadcom patch based on model number alone.

## Dangers, misinterpretations and concrete code gaps

1. **Stale prebuilt downloader:** ZIP's binary is byte-identical to previous snapshot despite source changes. Tests compile a test program, not the production executable. Require a fresh AArch64 build of the source and fingerprint binaries before use.
2. **Unverified download state machine:** Source still has code after a deliberately rejecting `--download` argument. Preserve that explicit refusal. A version reply, ACK/NACK, memory-write completion semantics, retransmission and hard failure boundaries must all be established before considering a live upload.
3. **Isolated trial not runnable out of ZIP:** `tools/s10plus/ssp-runtime/run_isolated.py` requires `lhd-isolated.conf`, `sha256-manifest.json`, AArch64 `isolation-probe`, a suitable `libssp-log-stderr.so`, and a matching system linker/closure. These files are **not yet supplied as runnable staged artifacts** in the archive. V2's `ssp_trial_prepare.py` provides config+manifest generation, not a Bionic runtime or compiled target objects.
4. **Unsafe sensor/GNSS power coupling:** `lhd.conf` actively names `GpioNPowerPath=/sys/class/sec/sensorhub/mcu_power` and `GpioNStdbyPath=/sys/class/sec/gps/GPS_PWR_EN/value`. The latter was linked historically to abrupt resets. Never unmask both merely to make `lhd` start. The stock config repeats `LheMaxMcuResetTries` (4 and 3); parsing precedence needs verification; V2 isolation config deduplicates this with value 0.
5. **Historical boots are not current:** Nov 13 #48/#78 traces, Nov 14 #3 snapshot, Nov 16 connection failures are different contexts. Report the kernel ID and collection timestamp with every new test; don't merge observations across boots.
6. **Sandbox static tests are limited:** verify namespaces, no actual device bindings, no network share, no capabilities, UID, restricted writable logs, and integrity for **all** files. Nuxel's existing test suite checks sandbox command shape, not a live isolation-run assertion.
7. **Offline build source absent:** the kernel patch verifier cannot be run on the original source from this ZIP. Request kernel source checkout at reported pinned commit and verify that header independently.
8. **No artificially generated nonzero data:** sensor streaming must pass physical movement tests with time-correlated distinct values from accelerometer and gyroscope, verified by a human moving the phone. A daemon returning available=true or synthetic orientation is insufficient.

## New V2 tools, actual scope

- `ssp_stock_collect.py`: host-side, read-only ADB extraction of matching vendor anchors and transitive ELF dependencies from already mounted stock Android system/vendor partitions. It **rejects hash mismatches**, never writes the phone, and saves source paths/hashes/build properties. It cannot mount partitions, unpack `.apex` packages, or conjure a missing matching Android system. Its default is a plan-only dry run.
- `ssp_trial_prepare.py`: host-only generation of a no-hardware-access config for an **isolated** `lhd` trial and file-integrity manifest. It does not run `lhd` or supply `linker64`/libraries.
- `ssp_live_snapshot.py`: read-only SSH snapshot of named sysfs endpoints. A classification of changing vectors is **not** an independent claim of actual physical motion.
- `test_recovery_v2.py`: self-contained offline regression tests for the new tools.

None of these utilities rewrite firmware or unlock restricted security boundaries. They are designed to give the agent the precise missing artifact and to enable controlled proof of progress without risking a speculative upload.

6. When verified firmware start and MCU runtime become available, validate real sensor samples, axis sign/remapping, interrupt flow, suspend/resume, cold and warm boot, and auto-rotate. Provide a repeatable transcript and test results.

## Unresolved dependencies beyond code
