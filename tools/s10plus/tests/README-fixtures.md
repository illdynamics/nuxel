# Camera-DT test fixtures

Two classes of fixtures:

## 1. Regenerated from DTS source (`fixture-src/*.dts` → `fixtures/*.dtb`)

Produced by `generate-fixtures.sh` (idempotent, deterministic). These exercise
the real device-tree *graph* checks in `camera-dt-gate.py`:

| Fixture | Expected | Defect exercised |
|---|---|---|
| `good-camera.dtb` | PASS | minimal valid Exynos9820 FIMC-IS camera DT |
| `broken-endpoint.dtb` | FAIL | `remote-endpoint` references dangling phandle `0x99` |
| `i2c-collision.dtb` | FAIL | camera `fimc-is_sensor@48` steals reserved touch @0x48 |
| `fimc-csis-conflict.dtb` | FAIL | native CSIS + vendor FIMC-IS2 co-bound with s5k sensor |
| `bad-lanes.dtb` | FAIL | `data-lanes=<0x1 0x2 0x3>` (3 lanes, invalid) |

## 2. Device-derived / historical (large `.img` containers)

These require the real Samsung DTH (`0xd7b7ab1e`) container and are NOT
regenerated by the script (they embed 8 MiB partition-size containers):

| Fixture | Expected | Defect exercised |
|---|---|---|
| `empty.img` | FAIL | zero bytes |
| `truncated-dtb.img` | FAIL | DTH container truncated before a complete FDT |
| `bad-magic-dtb.img` | FAIL | magic `0xdeadbeef` (not a valid container) |
| `wrong-board-dtb.img` | FAIL | root compatible `exynos9810` (not 9820) |
| `wrong-rev-dtbo.img` | FAIL | dtbo entry 0 rev window `[4..15]` excludes board rev 26 |

`wrong-rev-dtbo.img` is exercised with `--dtbo-idx 0` to prove the board
revision window check rejects a dtbo that does not cover the expected revision.

## Provenance

The device-derived fixtures are real Samsung `beyond2lte` DTH containers whose
property values were mutated to simulate a defect. They match the live sda12/
sda13 format exactly (8 MiB partition image, big-endian DTH header). See
`reports/camera-01-dt-gate.md`.
