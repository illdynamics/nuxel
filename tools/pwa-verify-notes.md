## 4. Bridge per-session token flow (manual spot-check)

`pwa/nuxel-common/bridge.js` token-resolution order is intact (verified by
inspection):

1. `window.__NUXEL_TOKEN__` (injected by the native PWA launcher)
2. `fetch('/var/lib/nuxel/.api-token')` (local API token file)
3. `localStorage['nuxel-bridge-token']` (dev fallback)
4. otherwise `POST {apiUrl}/auth/token` with `{app_id}` (per-session bootstrap)

Resolved tokens are attached as `Authorization: Bearer <token>` to every
`/api/v1/*` request (and persisted via `_persistToken()`). The node harness
(`test-bridge.js`) exercises exactly this flow against a mock server and all
assertions pass.

`pwa/nuxel-common/geolocation.js` exists and is a real geolocation passthrough
module (PWA → `bridge.call('location','request')` → bridge → GeoClue2/VM).
