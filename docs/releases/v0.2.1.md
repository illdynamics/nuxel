# Nuxel v0.2.1 — feature truth, Bluetooth confirmed, audio almost

**Released:** 2026-10-30  
**Device under test:** Samsung Galaxy S10+ SM-G975F (`beyond2lte`, Exynos 9820)  
**Kernel:** Samsung-derived Linux 4.14.253 with the Nuxel ABOX/Bluetooth patch  
**Userspace:** Fedora 43 aarch64, PipeWire + WirePlumber  
**Release transport:** merged PR to `main` → GitHub Actions builds the merge
commit, creates the annotated `v0.2.1` tag and publishes the release.

## Headline

This release aligns the feature list, launcher overlays and documentation with
the actual handset state:

- **Bluetooth is confirmed working.** The controller registers, powers on and
  scans peers.
- **Audio is almost complete.** The entire software route is verified; physical
  audibility is the remaining owner check.
- **Wi-Fi is ON by default at boot** through NetworkManager, with radio and
  network-link state reported separately.
- **Overlays never invent OFF.** Quick Settings, the status bar and the
  lockscreen use ON/OFF/UNKNOWN tri-state semantics backed by real providers.

## Bluetooth: what was actually proved

```text
nuxel-bluetooth.service  active (running)
  └─ btattach -B /dev/ttySAC1 -P h4 -S 115200
/sys/class/bluetooth/hci0 -> .../ttySAC1/hci0
Controller 43:75:B1:00:1F:AC (public)
  Powered: yes
12 s bluetoothctl scan on
  discovered 67:BC:9D:9D:37:7F
```

The bridge provider now reports `adapter_present`, `powered`, `discovering`,
`adapter_address`, rfkill state and the concrete blocker. Quick Settings maps
only an explicit boolean to ON/OFF; an absent or unreadable value stays UNKNOWN.
The top status bar and lockscreen light their Bluetooth glyph only for a powered
adapter; OFF and UNKNOWN remain dark.

**Not claimed:** a specific headset/keyboard profile test, sustained audio-over-
Bluetooth (A2DP) and Bluetooth file transfer. Pairing and connection verbs are
implemented and return the real BlueZ result.

## Audio: what was actually proved

```text
ABOX Calliope            MUB0
CS35L41 DSP1 (both)      booted=Y running=Y
Left/Right AMP PCM Gain  12 / 12 (GAIN_CTRL=0x193)
ABOX RDMA1_EN            1
Crossbar                 RDMA1 -> SPUS IN1 -> SPUS OUT1 -> SIFS1 -> UAIF1 SPK
PipeWire sink            alsa_output.hw_0_1, s16le 2ch 48000Hz
Default sink             alsa_output.hw_0_1 (verified readback)
RDMA1 runtime            state=RUNNING, advancing hw_ptr
Volume ceiling           25 %
pw-play                  rc=0
```

**Not claimed:** physical audibility. Repeated three-POW rounds played with
rc=0, but the owner-confirmation entry (`works` in a fresh, focused Notes title)
was not made. Microphone, wired headset and USB-C audio are untested. See
[`../../audio.md`](../../audio.md).

## Remaining blockers

- **Audio:** owner audibility, microphone capture and alternate outputs.
- **GNSS:** vendor BBD/LHD userspace missing (`BLOCKED_FIRMWARE`).
- **Camera:** no usable V4L2 capture node.
- **Cellular modem:** ModemManager finds no Shannon modem object.
- **External display:** no `CONFIG_DRM` / Type-C DP Alt Mode stack.
- **Sustained interaction:** owner acceptance for keyboard feel, haptics and
  long-running app use.

## Rollback

- Userspace: restore the timestamped `.nuxel-rollback.*` copies written by the
  live deploy, then restart the affected Nuxel services.
- Launcher: service-worker cache activation removes stale `v57`/`v56`
  namespaces automatically; a manual rollback must restore both `manifest.json`
  and `sw.js`.
- Audio: restore the previous `nuxel-audio-route.sh` and restart
  `nuxel-audio-route.service`; do not lower the 25 % safety ceiling.
