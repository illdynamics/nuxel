# Nuxel v0.7.5-beta — confirmed rotation, partial GPU acceleration

**Released:** 2026-11-01
**Device under test:** Samsung Galaxy S10+ SM-G975F (`beyond2lte`, Exynos 9820)
**Kernel:** Samsung-derived Linux 4.14.253, `4.14.253-gf7194c1d15ed-dirty #5`
**Userspace:** Fedora 43 aarch64, PipeWire + WirePlumber, WebKitGTK 2.54
**Release transport:** merged PR to `main` → GitHub Actions builds the merge
commit, verifies it, creates the annotated `v0.7.5-beta` tag and publishes the
release with `--latest`.

This release ships the PWNAGE-47000..54000 work: **rotation that actually holds
and touch that follows it**, and **partial GPU acceleration** with the Mali-G76
in the render path. The word *partial* is load-bearing — the sections below say
exactly which stage is accelerated and which is not.

## Rotation: why it was broken, and what fixed it

### The compositor transform was the working path

The live Phoc session exposes **`HEADLESS-1`**, not `DSI-1`. Its mode is
`720x1520`, and `wlr-randr --json` is the only truthful output inventory.

| canonical pose | compositor transform | scale | verified logical output |
|---:|---:|---:|---|
| 0° | `normal` | 2 | 360×760 |
| 90° | `270` | 1 | 1520×720 |
| 180° | `180` | 2 | 360×760 |
| 270° | `90` | 1 | 1520×720 |

The reverse 90/270 mapping is deliberate: it is the physical mapping recovered
from the historical configuration. `--transform 90 --scale 2` rotates the scene
but leaves the desktop at 760×360, which is the sideways-without-landscape-geometry
picture that produced the old "partial success" reports. Transform **and** scale
are now applied as one transaction.

### Successful rotations were being reverted

The later uncommitted code wrapped every successful mode change in a 75 s
"owner confirmation" trial that nothing ever confirmed, so a successful
transform reverted after 75 s. A normal `set` now commits only after live
readback; a failed apply restores the previous verified transform and keeps the
previous policy. `--trial` is explicit opt-in (15–90 s) for acceptance tests.

### Touch is not transformed by the compositor

Phoc 0.54.0 passes raw libinput touch coordinates through
`wlr_cursor_absolute_to_layout_coords()`; the wlroots cursor helper applies an
output transform to absolute pointer devices, **not** to touch. Landscape
desktops therefore had portrait-mapped touch. Measured on the handset: for a
live transform `270`, `nuxel-screenshot` returns the 720x1520 raw buffer and
`grim` returns the 1520x720 logical desktop, with `raw == np.rot90(logical, 3)`
to zero MAE. The portrait touch frame therefore has to be rotated 270°
clockwise into the logical desktop: matrix `0 1 0 / -1 0 1`.

`libnuxel-libinput-path.so` is already the single LD_PRELOADed input-discovery
owner inside Phoc. It now also reads `/run/nuxel-orientation/input.json`,
applies the matrix with `libinput_device_config_calibration_set_matrix()`, reads
it back, and records `/run/nuxel-touch-calibration.state`. An inotify thread in
the same shim makes the change immediate while the screen is idle. There is no
second daemon, no polling policy, no presenter touch rotation and no duplicate
matrix.

### The presenter must not rotate a second time

`images/s10plus/build-phone-rootfs-inside-fedora.sh` compiles
`tools/s10plus/a67/nuxel-wl-fb.c`. The rotation-capable code had been written
into the unused `a34` tree, while the live `a67` bridge had no orientation
support. `nuxel-wl-fb` remains the **sole `/dev/fb0` writer** and now only adds
`/run/nuxel-wl-fb.orientation` evidence: capture/panel dimensions,
requested/compositor transform, scale, and `presenter_rotation=0` /
`double_rotation=0`.

### Navigation

The host action arrived (`EVT nav:action recents locked=1`) while the
authoritative `/run/nuxel/security/lock-state.json` said `"locked": false`,
because the launcher's local boot-gate cache was stale. The launcher now
reconciles against `security.status` at startup, replays a host/dock action only
after the provider confirms `locked=false`, and never bypasses a genuinely locked
provider.

Recents also used `GET /api/v1/windows/list` against a POST-only route; GET is
implemented, native close is a separate `/api/v1/windows/close`, and the Recents
card has a real Close button and left-swipe close.

## GPU: exactly what is and is not accelerated

### Phoc — real Mali

- `GL_RENDERER=Mali-G76 MC12 (Panfrost)`, GLES 3.2.
- Phoc maps `libgallium_dri.so` and holds three `/dev/mali0` contexts with **0
  llvmpipe threads**.
- The kbase EGL build is pinned by absolute path
  (`/etc/nuxel/egl-kbase.json`) so a Mesa package update cannot silently reset
  glvnd to the stock library.

### linux-dmabuf without lying about modifiers

The renderer reports ARM tiled/SPARSE modifiers as well as LINEAR, while the
kbase Wayland exporter physically allocates a linear udmabuf. Advertising the
ARM modifiers made Mesa tag a linear buffer with a tiled modifier and the
compositor import stalled. `zwp_linux_dmabuf_v1` v3 now advertises **LINEAR
only** (AB24/XB24/AR24/XR24 + `MOD_LINEAR`) and validates plane/offset/stride/
dimensions before import: 20/20 valid buffers accepted, malformed ones
disconnect only that client, and Phoc survives.

### WebKit — GPU-rendered, SHM-presented

- Three `/dev/mali0` contexts and four `ThreadedCompositor` threads in the web
  process.
- 186 `KBASE_IOCTL_JOB_SUBMIT` calls (`_IOW(0x80,0x02,0x10)`) in 3 s: real GPU
  job submission, not a label on a software path.
- `WEBKIT_FORCE_COMPOSITING_MODE=1` selects `gpu-rendered-shm-presented`;
  **0 udmabuf/dmabuf FDs** are used by WebKit.

### The kernel ABI boundary (not a userspace bug)

WebKitGTK 2.54 uses the accelerated backing store only when `drmMainDevice()` is
non-null. This kernel has `CONFIG_DRM=y` but `CONFIG_DRM_VGEM` unset, no
`/dev/dri`, and `CONFIG_MODVERSIONS=y` without the exact `Module.symvers`, so an
out-of-tree `vgem.ko` cannot be loaded safely. Symlinking `/dev/mali0` to a fake
`/dev/dri/renderD*` was explicitly **not** done: kbase does not implement the
DRM ioctl ABI. True zero-copy presentation also needs DRM/KMS scanout;
`/dev/fb0` cannot import a DMA-BUF, so `nuxel-wl-fb` still copies each changed
frame on the CPU.

Decision record: `docs/beta-finalization/live/GPU-WEBKIT-WSI-DECISION.md`.

### Profiles

`/etc/nuxel/graphics/graphics-profile.json` (schema 2) exposes:

- `software-safe` — measured, default for Home/Settings/lockscreen;
- `gpu-rendered-shm-presented` — measured; Mali EGL rendering + SHM transport;
- `gpu-rendered-dmabuf-presented` — **unavailable**, loud fallback reason;
- `fully-accelerated` — **unavailable**, loud fallback reason.

| `nuxel-wl-fb` CPU | 10.6 % | 6.4–8.9 % |
| WebKitWebProcess CPU | 6.5 % | 3.1–4.7 % |
| Sum (one core, active UI) | 47.0 % | 27.8–31.3 % |
| Sum, post-reboot idle | — | 16.0 % |

## Kernel and platform

The handset runs capabilities the stock `exynos9820-beyond2lte` defconfig does
not enable. They are now part of the repository and part of the release gate:

| Capability | Why |
|---|---|
| `CONFIG_DRM`, `CONFIG_DRM_KMS_FB_HELPER`, `CONFIG_DRM_FBDEV_EMULATION` | Mesa/wlroots DRM-capable build |
| `CONFIG_DRM_EXYNOS=n` | the Exynos7 DECON DRM driver steals the vendor fbdev driver's name and removes `/dev/fb0` |
| `CONFIG_UDMABUF`, `CONFIG_DMA_SHARED_BUFFER`, `CONFIG_SYNC_FILE` | kbase ↔ wlroots buffer sharing |
| `CONFIG_MALI_MIDGARD`, `CONFIG_MALI_BIFROST_R26P0`, `CONFIG_MALI_REAL_HW` | vendor Mali-G76 kbase |
| `CONFIG_USER_NS`, `CONFIG_SECCOMP_FILTER`, `CONFIG_CGROUPS` | Flatpak/bubblewrap |
| `CONFIG_NFC`, `CONFIG_SEC_NFC`, `CONFIG_SAMSUNG_NFC` | vendor S3NRN82 controller |
| `CONFIG_DRM_VGEM=n` | explicit: no DRM/GBM node, hence no WebKit dma-buf |

`kernel/s10plus/configs/live-required.config` records the capability set read
back from the running phone (`zcat /proc/config.gz`), and
`tools/s10plus/verify-kernel-config.py` fails the release if the built
`.config` drifts from it.

Kernel patches added: `0006-sec-ts-lpm-bind` (touch binds in charger/LPM boot),
`0007-sec-nfc-class-name` (prevents a `sysfs_warn_dup()` panic), `0008-nuxel-userns-flatpak`
(removes the Samsung `current_chrooted()`/`LOD_SEC` user-namespace gates), and
`0009-nuxel-statx-mnt-id` (`STATX_MNT_ID` backport for Flatpak 1.16).

`/var/backups/nuxel/p54000-<UTC>` and prints its path. Userspace:

```sh
tools/s10plus/a67/rollback-pwnage54000.sh root@192.168.178.167 \
  /var/backups/nuxel/p54000-<timestamp>
```

GPU set:

```sh
tools/s10plus/a67/rollback-pwnage53000.sh root@192.168.178.167 \
  /var/backups/nuxel/p53000-20261101T143813

adb -s R58M75KDB2X shell 'sha256sum /dev/sda14'   # 574c239c...
```

## Honest limits

1. **WebKit DMA-BUF / fully-accelerated** — blocked by the kernel ABI (no
   DRM/GBM allocation node). Not claimed.
2. **GTK4 DMA-BUF import** — not claimed; GSK remains auto/cairo.
3. **CPU scanout copy** — `nuxel-wl-fb` copies changed frames into `/dev/fb0`;
   disclosed, not called zero-copy.
4. **Satellite GNSS** — `BLOCKED_FIRMWARE`.
5. **Fingerprint unlock** — device nodes exist, no verified TEE/trustlet
   provider in this rootfs.
6. **Camera, cellular modem** — not working.
7. **Charger-attached cold boot** — the LPM touch-bind code and BOOT image are
   deployed; the physical power-off/charger/power-on test is still an owner
   action.
8. **Clean rootfs image** — built and offline-verified; the live phone runs the
   deployed userspace delta, and the release ships both that hash inventory and
   the exact BOOT bytes.
