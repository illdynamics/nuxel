**Released:** 2026-10-31
**Device under test:** Samsung Galaxy S10+ SM-G975F (`beyond2lte`, Exynos 9820)
**Kernel:** Samsung-derived Linux 4.14.253 (vendor tree)
**Userspace:** Fedora 43 aarch64, PipeWire + WirePlumber, WebKitGTK 2.54
**Release transport:** merged PR to `main` → GitHub Actions builds the merge
commit, verifies it, creates the annotated `v0.7.4-beta` tag and publishes the
release with `--latest`.

the **build repair** that makes `main` green again. The GitHub Actions Release
workflow had been failing on `main` since the v0.2.1 merge (2026-10-30); the
failing step was the S10+ userspace regression gate, not the image build.

## Audio: the speaker is audible

The root cause was the CS35L41 PLL reference, not the digital route.

The device tree programs `ampclk = 6,144,000 Hz`, but ABOX UAIF1 actually
clocks the amplifiers at **1,536,000 Hz** (16-bit stereo 48 kHz). The protection
DSP therefore locked to the wrong reference and never drove the physical
speaker, even though every mixer control, ABOX crossbar and DSP1 firmware
reported healthy.

The owner-confirmed fix writes four registers on both amplifiers (`0x40` and
`0x41`):

| Register | Value | Meaning |
|---|---|---|
| `SP_RATE_CTRL` (`0x4804`) | `0x1b` | 1.536 MHz reference-clock entry |
| `PLL_CLK_CTRL` (`0x2c04`) | `0x370` | reference 1.536 MHz + PLL enabled |
| `AMP_DIG_VOL_CTRL` (`0x6000`) | `0x8000` | 0 dB, unmuted |
| `AMP_OUT_MUTE` (`0x2024`) | `0x0` | output/boost stage enabled |

### Why it persists

The raw writes alone were **not sufficient**: the pinned driver calls
`cs35l41_pcm_mute(dai, 1)` on every stream stop (`hw_free`), which rewrites
`0x6000 = 0xa678` and `0x2024 = 0x10`. A boot-time or pre-play raw write was
therefore wiped by the next playback's own power cycle.

The durable path is the driver's own cache:

- `Left/Right Digital PCM Volume = 817` → driver maps to `0x6000 = 0x8000`
- `Left/Right AMP Mute = Unmuted`
- `AMP Enable` on, `PCM Source = ASP`, `PCM Gain = 12`

`cs35l41_pcm_mute(0)` re-applies the cached `0x8000` and clears `0x2024` on
every playback start. Those controls are now part of
`nuxel-audio-route.sh`, so the state survives a reboot as well as a playback.

### The 366 ms cue and the warm-up helper

`nuxel-pow.mp3` is only ~0.366 s. On a cold path the `SPEAKER` / `Right AMP SPK`
DAPM widgets power up in the same instant the clip ends, so the cue is
swallowed even when every register is correct.

New `/usr/lib/nuxel/nuxel-audio-warmup`:

1. starts an inaudible 8 s 48 kHz stereo WAV at volume 0.0,
2. waits until `/sys/kernel/debug/asoc/beyond-madera/dapm/SPEAKER` is `On`,
3. re-asserts the driver cache and the proven registers,
4. then the caller plays the real POW once.

`nuxel-cs35l41-apply.sh` is the compatibility entry point. The helper is wired
into `nuxel-sound-cue` (boot cue and volume keys), `AudioProvider.test_audio`
(Settings → Sound → Test Audio), and the boot unit drop-in
`nuxel-boot-sound.service.d/20-warmup-keepalive.conf` (`KillMode=process` so
the keepalive cannot fail a successful cue).

## GNSS and location: almost

### What works

A genuine network-derived location is verified live across two reboot cycles:

```
latitude 51.4005  longitude 5.47196  accuracy ±25000 m  source network_wifi
```

### Root causes fixed

1. **GeoClue needs a per-UID agent.** GeoClue2 queues `Manager.GetClient`
   until an agent is registered for the calling UID; without one the call
   times out with `NoReply`. Embedding the agent in the bridge deadlocks,
   because `GetClient` blocks the bridge's single-threaded D-Bus loop while
   GeoClue calls back into that same connection. New
   `nuxel-geoclue-agent.service` runs as `nuxel-bridge`, exports
   `org.freedesktop.GeoClue2.Agent`, authorizes only `org.nuxel.Bridge` and
   re-registers after a GeoClue restart.
2. **The kernel blocks `AF_INET` without `CAP_NET_RAW`.** On this Samsung 4.14
   vendor kernel, `socket(AF_INET, SOCK_DGRAM)` returns `EACCES` for an
   unprivileged UID. GeoClue's Wi-Fi/IP source cannot resolve DNS without it.
   `geoclue.service.d/10-nuxel-network.conf` grants that single ambient
   capability to GeoClue only.

### Bridge and PWA correctness

- The bridge uses the real GeoClue 2.8.2 API: `DesktopId` and
  `RequestedAccuracyLevel` are read/write properties, `Location` is a
  read-only property (there is **no** `GetLocation` method), and `Timestamp`
  is a `(seconds, microseconds)` tuple.
- `pwa/nuxel-common/geolocation.js` never fabricates data:
  - missing/NaN/Infinity/out-of-range coordinates are rejected (never `0,0`);
  - a missing provider timestamp stays missing (never `Date.now()`);
  - unknown accuracy is `null`;
  - network/Wi-Fi/IP sources are never relabelled as GPS/GNSS;
  - one shared polling watch stops every timer when the last watch is cleared
    or location policy goes OFF.
- Maps and the Quick Settings location tile distinguish GNSS, network and
  stale fixes; the top-bar indicator is source-aware and hidden when OFF.
- `nuxel-gnss-diag.sh` and `configs/nuxel/gnss/gnss.json` are protocol-aware:
  `/dev/ttyBCM` is Broadcom BBD/LHD RPC, **not** NMEA, and stock `gpsd` cannot
  decode it.

### What is still blocked

Satellite GNSS is `BLOCKED_FIRMWARE`:

- no compatible BBD sensor-hub patch firmware (`bcm_sensorhub_a1.patch`);
- no Android/Bionic `lhd` + `gpsd` + HIDL runtime, which the vendor binaries
  need (`/system/bin/linker64`, `/vendor/...`).

`LocationConnector` therefore reports `gnss_fix=false` and
`fix_supported=false`. **No satellite fix, coordinate, accuracy value or
satellite count is claimed anywhere.** The outdoor owner procedure remains
`docs/beta-finalization/manual-proof/13-gps.md`.

## GTK applications: almost

- `shell/nuxel-shell/meson.build` builds the GTK4/libadwaita applications
  (dialer, messages, contacts, settings, permissions) when GTK4 and
  libadwaita are available; `shell/nuxel-home-native` is the GTK/Python Home
  twin.
- The S10+ ships the WebKit PWA launcher (`nuxel-pwa-host`) rather than the
  GTK shell, and the release image does not compile the GTK apps into
  `/usr/bin`. The GTK sources are buildable and tested offline; they are not
  the running handset shell.
- Dialer/Messages remain limited by hardware: ModemManager finds no modem
  object on this port, so calls and SMS are unavailable. The apps report the
  blocker instead of simulating a call.
- New for this release: `tools/s10plus/a45/nuxel-statusbar.c` is compiled into
  the image. It keeps the Nuxel top strip (clock, Wi-Fi, battery) visible over
  fullscreen native Wayland clients with an empty input region, so taps still
  reach the client below.

## Flatpak applications: almost

- The aarch64 Flathub packages for Firefox, VLC, Signal and Stremio are
  installed on the handset.
- **Flatpak cannot launch on this kernel:** `CONFIG_USER_NS=n`, so bubblewrap
  cannot create the sandbox's user namespace.
- Truthful wrappers are installed at `/usr/lib/nuxel/`:
  - `nuxel-flatpak-firefox` → execs the genuine Fedora aarch64 Firefox RPM;
  - `nuxel-flatpak-vlc` → execs the genuine Fedora aarch64 VLC RPM;
  - `nuxel-flatpak-signal` and `nuxel-flatpak-stremio` → exit 2 with the
    `CONFIG_USER_NS=n` explanation (no official aarch64 RPM exists, and a fake
    shortcut is not a launch).
- Registry revision 8 registers all eight installed native applications with
  their real install paths and `shell/config/*.desktop` entries. The registry
  verifier now accepts an installed package with a real desktop entry instead
  of requiring a repository source tree, and it still fails when either is
  missing.

## PWNAGE-41000..44000 feature work

### PWNAGE-44000 — Home, hardware controls, gallery and file sharing

- **Home drag/reorder.** One pointer state machine; primary-pointer ownership;
  pointer capture on the stable `#app-grid`; a complete model snapshot taken in
  `_startDrag` before any render and restored on
  `pointercancel`/`lostpointercapture`; live `elementFromPoint` hit-testing;
  edge-hover page switching; a drop outside the grid cancels instead of
  silently appending. A tap still launches only when the release is over the
  same icon.
- **Notes and widgets.** The persisted widget desktop is one-based and
  schema-1 documents migrate losslessly. The sticky Notes widget supports
  add/remove, note selection, open-note deep links, resize and long-press
  move, all persisted. Saves are serialized through a revision queue; "Saved"
  appears only after the write confirms, and a failed write keeps the content
  and stays dirty. `nuxel:notes-updated` synchronises Home and an open Notes
  app.
- **Performance.** Files uses one delegated listener, `DocumentFragment`
  batches of 120 and stale-render tokens. Measured 1000-entry synthetic
  render (linkedom, 20 iterations): **p95 59.74 ms → 34.27 ms (−42.6 %)**.
  Live Gallery thumbnail: cold 2,163 ms, cached 35 ms (**−98.4 %**).
- **A34 power menu.** All 15 configured entries are compiled into the button
  manager (including Back, Forward, Stop loading and Reload launcher).
  Recovery/Download remain refused with `NO_FLASH_INVARIANT`; the reboot gate,
  cooldown, hourly cap and rollback-path requirement are untouched. Live OSD
  confirmed `kind power-menu count 15`.
- **Screenshot.** `tools/s10plus/a68/nuxel-screenshot.c` is compiled by the
  image builder to `/usr/lib/nuxel/nuxel-screenshot`, which is the path
  `nuxel-pwa-host` calls. Capture is Wayland screencopy (never a second
  `/dev/fb0` writer); the host bounds the child to 10 s, converts P6 to PNG,
  writes atomically into `/home/nuxel/Gallery` and only then raises a toast.
- **Gallery thumbnails.** `pwa_store.storage_thumbnail()` validates canonical
  paths, rejects traversal/symlink escape, picks `ffmpeg` → `mpv` → GStreamer
  with argv + `shell=False` + hard timeouts, writes atomically and caches by
  path + size + mtime. `POST /api/v1/rpc storage.thumbnail` and
  `GET /api/v1/storage/thumbnail?path=` serve controlled JPEG.
- **Files send.** Bluetooth OBEX ObjectPush1 through BlueZ, waiting for
  `Status=complete`, with traversal/symlink/`>20 files`/`>512 MB` guards and
  honest success/failure. Wi-Fi Direct and Nearby are visibly disabled.
- **Flashlight.** One owner (`flashlight_provider.py`) writes brightness to
  `torch-sec1` only, enforces a 60 s maximum, explicit OFF on
  timeout/exit/toggle, camera arbitration and a thermal guard. It reports
  `NOT_SUPPORTED_ON_DEVICE` / `BLOCKED_CAMERA` / `THERMAL_LIMIT` rather than a
  fake ON.
- **Status and expanded Quick Settings.** Location, sound mode and a compact
  USB cell (`file`/`term`/`chrg`) sit in the top bar; a charging-only
  lightning bolt appears inside the battery; expanded Quick Settings shows
  charging vs external power, USB host, active vs selected file transfer and
  live console state.

### Remaining owner-dependent checks

- Physical touch proof of long-press drag, sticky-widget resize/move and the
  Notes deep link after reboot.
- A physical Bluetooth transfer needs a second paired OBEX receiver.
- Visible torch illumination is proven only by the LED node changing
  0 → 15 → 0; the owner should confirm visually during a bounded ON.

## Rollback

- Userspace: restore the timestamped `.nuxel-rollback.*` copies written by the
  live deployment, then restart the affected Nuxel services.
- Audio: `/root/pwnage-40000/frozen-state/` on the device holds the confirmed
  scripts, the silence asset, `state.txt`, `confirmed-midplay.txt` and hashes.
- Boot: flash the previous BOOT partition backup; this release does not change
  the BOOT bytes.
- Systemd: disable `nuxel-audio-route.timer`, `nuxel-geoclue-agent.service` and
  `nuxel-mtp.service`, then `systemctl daemon-reload`.
