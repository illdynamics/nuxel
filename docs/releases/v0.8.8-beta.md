# Nuxel v0.8.8-beta — PenGuru Squad opt-in AI beta and synchronized version lockstep

**Release date:** 2026-11-17
**Canonical version:** [`VERSION`](../../VERSION) = `v0.8.8-beta`
**Feature branch / release source:** `feat/png` → merged to `main` (see final report)
**Primary target:** Samsung Galaxy S10+ (`s10plus`, Exynos9820 / beyond2lte)

## Headline

This release integrates an **opt-in, disabled-by-default local AI subsystem
("PenGuru Squad")** on top of the already-booting S10+ image, closes the Phase-0
security gates (G0) that the dual-runtime guide marks as prerequisites for any
privileged PenGuru action, and synchronizes the whole repository to a single
canonical version `v0.8.8-beta` behind a passing release-asset lockstep gate.

PenGuru stays **chat-only** in this beta. No model is allowed to perform a
privileged system action by returning persuasive text; every bridge/system call
passes a typed, separately enforced permission boundary. The subsystem does not
phone home — no cloud inference, no telemetry, no always-on worker.

## PenGuru components actually deployed

- Native service `nuxel-penguru.service` + download unit `nuxel-penguru-download.service` (systemd units in `services/nuxel-penguru/systemd/`).
- Bridge HTTP route + Unix IPC control socket (`/run/nuxel-penguru/control.sock`), launcher-token gated.
- PWA **PenGuru Squad** app under `pwa/nuxel-apps/penguru`, Settings tab **PenGuru AI**.
- Installer / rollback tools: `tools/install-device.py`, `tools/rollback-device.py`, `tools/build-worker.sh`. Each install prints a receipt under `/var/backups/nuxel-penguru/`; rollback restores newest receipts first.

## Supported models and runtimes

- Runtime backend: pinned **llama.cpp** (ARM64 shared lib, GGUF) — revision `de32b268c4ad55d45f3b7b16c029f4e077f4ba74`.
- Candidate models: ChatBird `Impish_LLAMA_4B_Abliterated-Q4_K_M`, CodeBird `Qwen3.8-4B-Q4_K_M` (manifests in `services/nuxel-penguru/manifests/`).
- **Gate:** model download/install is disabled until a manifest is signed with the production trust key, the owner acknowledges the immutable revision + license, and a real runtime self-test reports READY. Repository manifests are unsigned by design; the menu shows the exact trust failure rather than pretending otherwise.

## Security and privacy controls (Gate G0 — closed & regression-tested)

- **P0:** dev-mode loopback no-token bypass neutralized; every session token bound to a launcher-authenticated app identity; `token.app_id == request.app_id` enforced for all verbs. Unauthenticated loopback → 401; forged/replayed/mutated identity → rejected (`test-security-g0.py`).
- **P1:** `once` grants are consumed at the permission authority and bound to one immutable action/request ID (no reuse); `session` grants bind to a real session with revocation; unknown capability ids are dropped. Regression proves first `once` succeeds, second fails in the same daemon lifetime.
- **Supervisor boundary:** the model cannot elevate itself to a privileged system action by text alone — all bridge/system calls pass the typed permission broker (`read_actions.py`) and canonical `capabilities.json`.
- **Privacy:** local-only; wake-word / microphone listening disabled by default; no background telemetry; models and signing keys never enter Git.

## Known limitations

- Repository model manifests are **unsigned**; production signing key integration is not finalized, so multi-GB model downloads cannot be initiated from the repo tree in this release.
- ONNX GenAI export path for ChatBird/CodeBird (Phase 1 guide steps 13–14) is not shipped; llama.cpp GGUF is the only backend in this beta.
- Voice / wake-word modes are intentionally out of scope and disabled.
- Live on-device performance, battery and thermal figures are **not measured** in this build environment (`BLOCKED`); do not treat any number as verified.
- Five pre-existing test failures in `tests/pwnage90000/test_pwnage90000.py` (hardcoded whitespace contracts, a service-worker cache-assertion mismatch, and a missing generated `SYSTEMD-GRAPH.md`) exist on the base commit and are **not** introduced by this release; they were left unchanged rather than weakened to force a pass.

## Installation, opt-in, disable and rollback

Installation runs **on the handset as root** with a staged repository tree:

```sh
sh services/nuxel-penguru/tools/build-worker.sh \
  /root/penguru-build/llama.cpp /tmp/penguru-llama-worker
python3 services/nuxel-penguru/tools/install-device.py \
  --source-root "$PWD" --worker /tmp/penguru-llama-worker
python3 services/nuxel-penguru/tools/device-api-check.py
```

The installer merges only the PenGuru registry entry, Settings tab/section and
bridge route; it preserves unrelated live changes, existing signed manifests,
models and trust keys, then restarts the HTTP bridge (existing app tokens must
be refreshed). The service is **disabled by default** (`systemctl disable`).

Opt-in: open Nuxel Settings → **PenGuru AI**, enable the beta, choose a model,
acknowledge its immutable revision + license, and run the runtime self-test to
reach READY. To disable / uninstall:

```sh
python3 services/nuxel-penguru/tools/rollback-device.py \
  /var/backups/nuxel-penguru/TIMESTAMP/receipt.json
```

Restore newest receipts first; rollback refuses post-install file edits and does
not remove model data, trust keys or the service account.

## Other hardware limitations carried into this release

Satellite GNSS (`BLOCKED_FIRMWARE`), USB-C HDMI (needs `CONFIG_DRM` + DP Alt
Mode), camera capture (no usable V4L2 node) and the Shannon modem (no
ModemManager object) remain honestly blocked, unchanged from v0.8.7-beta.
