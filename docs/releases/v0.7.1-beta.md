## What shipped

PWNAGE-30000 turns the application shells into working, durable app flows and
adds the shared layers they need:

| Area | Result |
|---|---|
| Bridge persistence | `pwa_store.py` provides atomic file-backed Calendar, Notes/keys, Contacts and traversal-safe Files storage; the dead D-Bus storage/CalDAV method routes are replaced |
| Mail | `mail_client.py` performs TLS-only IMAP/SMTP discovery and connection tests; passwords are never stored or logged; fetch/send stays `NEEDS_CREDENTIALS` until the owner supplies credentials |
| Calendar | Durable save/delete, validation, all-day/location/reminder fields, duplicate-save lock, edit/delete and platform date/time pickers |
| Clock | Working tab switching; timer/stopwatch/alarm lifecycle retained; alarm persistence and haptics on ring |
| Files | Full browser with breadcrumbs, selection, CRUD, copy/cut/paste, ZIP create/extract, upload and traversal/symlink protection |
| Notes | Durable autosave plus explicit save with dirty/saved/error state; search, pin and export retained |
| Weather | Live Open-Meteo geocoding and forecast with manual city lookup and stale-cache/offline states |
| Gallery / Recorder | Gallery renamed and sample PNG seeding verified; Recorder writes a real 16-bit PCM WAV |
| Theme / haptics / widgets | Nuxel Grove (default) and Test Theme, shared haptics FIFO client, per-desktop widget registry and Notes widget |
| Nuxtore / Settings | Shared theme tokens and the Settings Appearance page; Nuxtore remains honestly verification-gated |

Carried forward from v0.7.0-beta: the Tri-Link serial/Wi-Fi/USB consoles, the
unlock → Home repair, canonical GPS/Maps state and the Bluetooth/Location/Audio/
Displays provider pages.

### Service ownership repair

After the first restart, `nuxel-web` failed with
`OSError: [Errno 98] Address already in use`. The launcher session had started
its own `python3 -m http.server 8000` fallback before `nuxel-web` bound the
port. The live host was repaired by stopping that fallback and starting
`nuxel-web`; the source fix removes the race:

- `nuxel-web.service` remains the only owner of `127.0.0.1:8000`.
- `nuxel-session.sh` starts its development fallback on `127.0.0.1:8001` only
  when nuxel-web is unreachable.
- `nuxel-wayland.service` is ordered `After=`/`Wants=nuxel-web.service`.

## Remaining owner acceptance / blockers

1. Physical touch-driven acceptance of Calendar, Clock, Contacts, Files, Mail,
   Notes, Weather, Gallery, Recorder and the desktop-2 Notes widget.
2. Vibration-motor feel and keyboard keypress haptics.
3. Real microphone capture and WAV playback/file placement on the device.
4. Real IMAP/SMTP send/receive with owner-supplied credentials.
5. Existing hardware blockers: Bluetooth HCI transport (`CONFIG_BT_HCIUART`
   unset), GNSS firmware/reader, USB-C HDMI/`CONFIG_DRM`, and the MADERA
   `HPOUT1 Digital` unmute D-state.

A green release workflow is not a hardware claim. This document separates the
live deployment receipt above from the physical acceptance tests that remain
open.

## Rollback

Each deployed target retains `.nuxel-rollback.pre-<operation>` plus the
long-lived `.nuxel-rollback` baseline. The transaction journal is
`docs/beta-finalization/live/evidence/pwnage-30000-live/transaction.jsonl`;
the deployment records the affected services (`nuxel-web.service`,
`nuxel-http-bridge.service`). No partition, boot image or kernel was modified.
