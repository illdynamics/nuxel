# Nuxel v0.7.7-beta — real WAD engine, engine comparison, global immersive chrome

**Release date:** 2026-11-04  
**Canonical version:** [`VERSION`](../../VERSION) = `v0.7.7-beta`  
**Primary application:** `org.nuxel.Doom` version `2.0.0`

## Headline

**Nuxel Doom is now a real WAD engine.** The original lookalike raycasting
engine is gone. `org.nuxel.Doom` embeds **Chocolate Doom 3.0 compiled to
WebAssembly** and loads actual Freedoom or imported IWAD/PWAD maps. It warps
into a real map, renders real geometry and textures, and drives the engine
through the touch HUD.

The release also adds two native comparison engines:

- **Chocolate Doom** (`org.nuxel.Doom.Chocolate`, native Fedora 3.1.1)
- **UZDoom** (`org.nuxel.Doom.UZDoom`, modern GZDoom lineage, software renderer)

Each is a separate NuXtore package with its own install/remove lifecycle.

## Changed

- Nuxel Doom manifest/app metadata bumped to `2.0.0`.
- NuXtore catalogue stages three packages: `org.nuxel.Doom` 2.0.0,
  `org.nuxel.Doom.Chocolate` and `org.nuxel.Doom.UZDoom`. All are signed with
  the repository's development-fixture Ed25519 key and verified offline.
- App registry revision 14 records the comparison apps and promotes Nuxel Doom
  to `complete`.
- **Every foreground app is immersive by default**, not only apps that request
  it. The top bar and triple buttons are hidden; bottom-edge swipe reveals
  navigation, top-edge pull reveals the status bar. Home and lockscreen remain
  exempt.
- **Native apps get the same reveal gesture.** `nuxel-navdock` now keeps a
  14 px transparent bottom strip when an app is foreground instead of
  unmapping. Swiping up on the strip reveals the full three-button dock for a
  few seconds; Recents kills or minimises the app. `nuxel-statusbar` mirrors
  that contract at the top edge: a 12 px strip expands to the full bar on a
  downward swipe and auto-collapses. Neither strip is mapped while the
  lockscreen is active.
- **Portrait boot until unlock.** `nuxel-orientationd` detects the first start
  of each boot, records the previously selected mode, and applies portrait
  before the lockscreen settles. Home holds that pose through the lockscreen
  and asks for the recorded mode only after a successful unlock. A daemon
  restart in the same boot does not force another rotation.
- The app launch path explicitly dismisses the OSK after an app becomes ACTIVE.
- The S10+ rootfs builder installs `chocolate-doom` and the Freedoom packages.
- The live userspace payload includes the Doom apps, engine artifacts, NuXtore
  catalog and WAD bridge module.

## Fixed

- Maps were empty in the previous Nuxel Doom because it was not a WAD engine.
  The app now renders real WAD geometry.
- The Doom app no longer contains an animation-frame raycaster masquerading as
  Doom; the old `doom-engine.js` is not loaded or shipped in the app shell.
- No keyboard is opened by any Doom screen: there are no text inputs, focus is
  blurred, and the host/compositor dismiss actions run at launch/focus/resume.
- The engine cannot leave a held key behind: pointer cancel, capture loss,
  blur, visibility change, pause and exit all emit key-up for every held key.
- The fullscreen chrome contract no longer depends on an app opting in.

## Known limits

- Nuxel Doom's engine saves live in the WebAssembly memory file system for the
  session; persistent game saves are a follow-up. Settings and WAD selection
  persist in `localStorage`.
- Native Chocolate Doom/UZDoom use keyboard or gamepad input, not the touch HUD.
  The Nuxel touch experience belongs to the WASM engine.
- UZDoom runs with its software renderer because the vendor kernel has no
  usable `/dev/dri` node. No GPU claim is made for it.
- Music is disabled on every Doom path on this image; the OPL/MIDI route is not
  working.
- Physical thumb-feel and speaker-route acceptance remains an owner check. The
  automated tests prove the input/chrome contract, not the panel.
