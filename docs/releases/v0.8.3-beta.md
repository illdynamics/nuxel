# Nuxel v0.8.3-beta — fully black screen-off, per-device completion and a repaired release gate

**Release date:** 2026-11-10  
**Canonical version:** [`VERSION`](../../VERSION) = `v0.8.3-beta`  
**Primary target:** Samsung Galaxy S10+ (`s10plus`, beyond2lte)

## Headline

Screen-off is now **actually off**. The S10+ AMOLED previously darkened but
kept a faint minimum luminance because brightness 0 left
`actual_brightness=2`, and `bl_power=4` alone did not clear the last latched
DECON frame. The active A67 presenter now paints and latches a black
framebuffer page, then drives the panel through the strongest powerdown path
the vendor kernel exposes.

## Screen-off sequence

The screen-off path in `tools/s10plus/a67/nuxel-wl-fb.c` is now:

1. Save the current brightness.
2. `memset()` the visible framebuffer to zero and commit it with
   `FBIOPAN_DISPLAY`.
3. Write brightness 0.
4. Write `bl_power=4` (`FB_BLANK_POWERDOWN`).
5. Issue `FBIOBLANK(FB_BLANK_POWERDOWN)`.
6. Re-assert `bl_power=4` after the ioctl and log the readbacks.

The bridge keeps its single `/dev/fb0` owner. No framebuffer fd is closed and no
second writer is introduced. On wake, the existing two-phase wake path forces a
fresh capture and commit before restoring the backlight, so the black page is
never shown after a successful wake.

## Release CI repair

The v0.8.2 `main` release run failed in the **Nuxel Home — immersive chrome**
source-contract step:

- The controller used one combined `BANDS` table; the contract expected named
  `BOTTOM_BAND` / `TOP_BAND` bands.
- The top-pull check expected a historical one-line call even though the shipped
  controller correctly defers shade advancement to Quick Settings.
- The native status bar exposed `bar_show`; the contract expected
  `bar_reveal`.

The v0.8.3 source now satisfies the contract without changing the runtime
behaviour:

- `pwa/nuxel-home/js/immersive.js` defines named `BOTTOM_BAND` and `TOP_BAND`
  constants and keeps the existing gesture/Quick Settings handoff.
- The contract check follows the real `dy > 0` branch and
  `setStatusVisible(true, 0)` call.
- `tools/s10plus/a45/nuxel-statusbar.c` names the reveal path `bar_reveal`.

## Regression gates

- `tools/s10plus/a34/tests/test-decon-presentation-contract.py` now fails
  closed unless the active A67 source contains the black-page latch, the zeroed
  visible framebuffer, the powerdown call and the post-FBIOBLANK `bl_power`
  re-assert.
- `pwa/nuxel-home/tests/test-immersive-chrome.js` passes 36/36.
- `tests/pwnage90000/test_release_assets.py` passes with the whole-repo
  `v0.8.3-beta` lockstep and the `v095-p106000` service-worker cache namespace.

## Deployment

The updated userspace (`v0.8.3-beta`) and the newly compiled A67
`nuxel-wl-fb` were deployed to the S10+ at `10.20.30.16` over SSH. The live
bridge state and the panel sysfs nodes were checked after
`nuxelctl display on` → `nuxelctl display off`:

- `dmesg`: `PANEL_BLACK why=screen-off bytes=17510400 pan_rc=0`
- `bl_power=4`
- `DISPLAY_OFF ... actual_brightness=2 ... black=1`
- visible framebuffer samples at the start, middle and end are all zero
- wake restored `DISPLAY_ON` with `bl_power=0`

The GitHub release build is triggered by merging this release PR to `main`; the
workflow builds the S10+ boot image and Fedora phone rootfs from repo sources,
verifies the artifacts, creates the annotated `v0.8.3-beta` tag and publishes
the release marked **Latest**.
