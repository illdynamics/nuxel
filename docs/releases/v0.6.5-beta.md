# Nuxel v0.6.5-beta — candidate and known acceptance blockers

This is a **source / CI candidate built by the GitHub Actions release
workflow**, not a hardware-certified daily driver.

The release is produced from the exact merged commit on `main`: the workflow
builds the S10+ boot image and Fedora 43 ARM64 userspace, verifies source
parity, then creates the annotated `v0.6.5-beta` tag and publishes a GitHub
prerelease. The phone is **not required to be connected** for that build — the
release additionally ships the captured installed-phone boot image
(`release/s10plus/`) so the exact image on the handset is part of the release.

## Implemented in this release

- **Whole-repo lockstep at `v0.6.5-beta`.** `VERSION` already said
  `v0.6.5-beta`, but device `APKBUILD`s, PWA/bridge manifests, bridge/portal/
  notifications hosts, systemd `Environment=` pins, shell apps and OTA/VM
  tooling still said `0.6.3-beta`. All are aligned now.
- **Release gate repaired.** Two CI gates hard-coded `0.6.3-beta`, so every
  `main` release run after the version move failed at
  `tools/s10plus/a43/test-a43-source.py`. Both now derive the expected version
  from `VERSION`. A stale A35 DECON brace-layout assertion was also corrected
  to test the real "every changed frame is committed" invariant.
- **Radio/privacy truth on the PWA bridge.** `permissions.request`,
  `network.wifi-*`, `bluetooth.*` and `location.*` never fall back to mock
  success; an unavailable provider returns an explicit error. `RequestScan` is
  bounded to 5 s and capability-grant loading tolerates malformed or policy
  files instead of failing bridge startup.
- **Launcher cache `v44-a76-lockstep`** for the changed launcher/bridge assets.

## Hardware blockers / pending tests

| Surface | Status | Required real-world evidence |
|---|---|---|
| S10+ boot of this release | CI-built, device not connected | Flash the published image and confirm boot to launcher |
| Wi-Fi association/internet | Bridge bounded, device unverified | NM Wi-Fi device, scan, WPA association, DHCP, DNS, HTTPS |
| Bluetooth / Location quick settings | Backends wired, device unverified | Real controller pairing; real location policy state |
| USB detach safety (A74) | Kernel fix in tree, physical acceptance pending | Owner unplug test with no lock-up |
| Audio speaker + cue | Blocked pending on-device evidence | ALSA card, DAPM route, audible owner confirmation |
| Camera | Samsung ISP/driver may be unsupported | Actual front/rear captured frames |
| NFC / GNSS / sensors | Driver availability unknown | Physical tag, GNSS fix, sensor channels |

A green GitHub Release is **not** proof of on-phone function. It proves the
declared sources built, verified and packaged exactly as committed.

## Release route

**Only a merged PR to `main` triggers a release.** `main` is protected and
requires a pull request. Tag pushes deliberately do not trigger the workflow;
the tag is created by the workflow itself once every gate is green.
