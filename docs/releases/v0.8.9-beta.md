# Nuxel v0.8.9-beta

Status: release preparation in progress; publication is not yet verified.

## Delivered and verified on the S10+

- Wi-Fi SSH deployment to `root@10.11.12.99`, Linux 4.14.253, ARM64.
- PenGuru Squad app and PenGuru AI Settings, using `assets/nuxel-penguru-squad.png`.
- Foreground model downloads with progress, cancellation, deletion and runtime selection.
- Owner-local Ed25519 release trust enrolled; previous test trust backed up.
- Immutable upstream GGUF file sizes and SHA-256 metadata rechecked before signing.
- Launcher-authenticated enable/status, three model cards, read-only battery route,
  cross-app token rejection and OFF checked on-device.
- READY requires owner license acknowledgement and a manifest-bound self-test.

## Incomplete acceptance gates

ONNX Runtime GenAI and compatible exports, learned SonarBird routing, microphone
STT/wake phrase, privileged writes and full thermal/soak acceptance remain open.
The UI must not advertise those as working. Deterministic Squad routing is the
available fallback. ChatBird licensing provenance remains unresolved; weights
are not redistributed. No model license is accepted merely by enrolling trust.

## Build and deployment identity

Active repository version pins are v0.8.9-beta. The phone-image build includes
PenGuru services and a CPU llama.cpp runtime built from immutable revision
`de32b268c4ad55d45f3b7b16c029f4e077f4ba74`. The live payload includes PenGuru
sources, app assets, manifests and public key. Services default OFF.

A live userspace update is not proof that a future CI rootfs image is byte-identical
to the running filesystem. Release tag, PR and workflow evidence will be recorded
only when those operations have completed.

## Repair of the preceding failed CI kernel build

The previous main workflow failed with undefined NCM cleanup and experimental
SSP symbols. NCM now unregisters its generated function directly before singleton
shutdown, matching the existing local source fix. The release patch set does not
include the experimental native SSP peer: its bring-up sysfs request now returns
`EOPNOTSUPP`, and diagnostics retain the real stock driver state. This does not
claim native sensor-hub bring-up support or enable experimental hardware code.
The captured installed boot asset and a CI-rebuilt kernel are distinct artifacts.
