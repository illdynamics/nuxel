# Nuxel v0.6.3-beta — candidate and known acceptance blockers

This is a **source / CI candidate**, not a hardware-certified daily driver.

## Implemented in this patch

- Single NetworkManager Wi-Fi control pathway shared with the launcher; a new
  Wi-Fi Settings tab supports real NM state, scanning, radio control, WPA2/WPA3
  connection initiation and disconnection. Requires working kernel Wi-Fi,
  firmware, D-Bus authority and a live owner association test.
- Corrected dock artwork stacking and retained independent BG1/BG2 selection,
  plus gesture improvements and suppression of Home-only pinch zoom.
- S10+ release build remains the source-built A34 boot + Fedora ARM64 rootfs;
  GitHub Actions release source is pinned to a merged commit or tag.
- Existing browser, file explorer, telemetry and diagnostics retained.

## Release route

**Only a merged PR to `main` triggers a release.** `main` is protected and
requires a pull request; tag pushes and direct branch pushes are not release
triggers.

1. Push a feature branch and open a PR. Never push `main` directly.
2. Merge the PR after review. The resulting `push` to `main` runs the S10+
   image builder from the merge commit.
3. After every build and artifact gate passes, the workflow creates the
   annotated `v0.6.3-beta` tag on that exact merge commit and publishes a GitHub
   **prerelease**. It also packages the hash-manifested live userspace payload
   generated from the same checkout.
4. A later `main` merge that leaves `VERSION` unchanged skips the build instead
   of rebuilding or overwriting the published release.
5. Verify with `gh run list --workflow release.yml --branch main`,
   `gh release view v0.6.3-beta`, and `sha256sum -c SHA256SUMS.txt` on the
   downloaded S10+ archive.

For operator recovery only, the workflow can be dispatched manually. It never
overwrites an existing release.

Never flash the image during a live userspace deployment. Keep the USB console
and known-good rollback available.
