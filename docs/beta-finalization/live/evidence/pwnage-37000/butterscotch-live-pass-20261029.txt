1. Wi-Fi boot policy (fixed first)
----------------------------------
problem: nuxel-wifi.service ran `rfkill unblock wifi` + `nmcli radio wifi on`
unconditionally on every boot, re-enabling a radio the owner had turned off.

fix:
- services/nuxel-s10/bin/nuxel-wifi-up.sh: read the authoritative
  `nmcli -t -f WIFI radio` state; exit immediately when disabled. Never
  rfkill-unblock, never `nmcli radio wifi on`, never rewrite
  connection.autoconnect, never run a blocking `nmcli connection up`.
- services/nuxel-s10/systemd/nuxel-wifi.service: description updated.
- services/nuxel-s10/bin/nuxel-apply-pwnage36000.sh: removed forced
  `rfkill unblock wifi`, `nmcli radio wifi on` and profile autoconnect rewrite.

verified on-device:
- systemd-run transient: radio off -> script ran -> after-script-radio=disabled
  -> re-enabled -> radio=enabled. Log:
    nuxel-wifi: Wi-Fi radio disabled by owner; leaving it off
    after-script-radio=disabled
    after-reenable-radio=enabled
- after reboot the saved "Nuxel Ziggo5501109" profile autoconnected without the
  unit forcing the radio on.

2. Boot latency (spinning-penguin path)
---------------------------------------
problem: multi-user.target was serialized behind nuxel-abox-firmware-reload and
nuxel-audio-route, and nuxel-wayland took the default 90 s stop timeout when the
ABOX reload stopped/restarted the session. On a session restart the preload
controller's already_ran path returned without republishing the PWA status file,
so the launcher's opaque preload cover polled a missing preload-status.json for
its full 40 s hard timeout.

fixes:
- services/nuxel-s10/systemd/nuxel-wayland.service.d/30-fast-stop.conf:
  TimeoutStopSec=8, SendSIGKILL=yes, KillMode=control-group. The ABOX wrapper
  restarts the session immediately after stopping it.
- removed stale multi-user.target.wants symlinks for
  nuxel-abox-firmware-reload.service and nuxel-audio-route.service on the
  device; both remain started via nuxel-wayland.service.wants /
  nuxel-boot-sound wants so audio still initializes, just not on the UI path.
- services/nuxel-s10/systemd/nuxel-audio-route.service:
  WantedBy changed to nuxel-wayland.service.
- services/nuxel-s10/bin/nuxel-abox-firmware-reload.sh:
  bounded the `echo on > power/control` resume write with timeout (mirrors the
  already-bounded suspend write).
- services/nuxel-preload-cinema/nuxel-preload-cinema:
  already_ran path now republishes a terminal `done` overlay/status file.
- pwa/nuxel-home/js/app.js:
  preload-cover poll backs off exponentially (100 ms -> 1 s) on missing
  preload-status.json instead of hammering every 100 ms for 40 s.
