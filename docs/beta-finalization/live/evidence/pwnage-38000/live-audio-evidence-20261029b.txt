ROOT CAUSE FOUND
----------------
`ABOX RDMA1_EN` (amixer numid=1031, enum Off/On, card 0) was `values=0` (Off).
Every other gate was already correct (AMP enables on, AMP Mute Unmuted, DSP1
Protection firmware item 9 + preload on, SPKAMP_EN on, SPKAMP_A/B=RDMA1,
SPUS IN1=RDMA, SPUS OUT1=SIFS1, SIFS1=SPUS OUT1, UAIF1 SPK=SIFS1, SIFS1 OUT
and UAIF1 switches on). With RDMA1_EN=Off, aplay/pw-play return 0 and hw_ptr
advances, but the ABOX never clocks RDMA1 samples into SPUS, so the CS35L41s
stay silent.

The previous 2026-10-28 route script had been "corrected" with the comment
"There is no 'ABOX RDMA0_EN' / 'ABOX RDMA1_EN' mixer control on this card",
which was wrong for RDMA1_EN, so the script stopped programming it.

FIX
---
services/nuxel-s10/bin/nuxel-audio-route.sh now issues:
    mix 'RDMA1_EN on' cset name='ABOX RDMA1_EN' 1
and verifies it in the read-back loop. Deployed to
/usr/lib/nuxel/nuxel-audio-route.sh (backup kept as .bak-<epoch>).
