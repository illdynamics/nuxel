## 2. Root causes found in this cycle (each one measured, not assumed)

| # | Symptom (user report) | Root cause (measured) | Evidence |
|---|---|---|---|
| R1 | animation frames appear through/over the launcher | **Two processes write the same `/dev/fb0` scanout memory**: the initramfs `nuxel-anim-player` (looping forever) and `nuxel-wl-fb`, simultaneously, for the whole session. The A30 handoff code exists in `tools/s10plus/a29/nuxel-wl-fb.c` but the **installed** binary is still A29: its state line has no `owner=`, and `fps_1s=total` reproduces the A29 reporting bug | `ps` (both live, 42%/65% CPU); `/run/nuxel-wl-fb.state`; `/var/lib/nuxel/anim-stop` absent; `ANIM_STAGE=MP4_PLAYER_ACTIVE` |
| R2 | no wallpaper | `/pwa/nuxel-home/assets/nuxel-background.png` is **404 on the handset**: `assets/pwa/**/assets/nuxel-background.png` is git-ignored (single-source asset regenerated by `tools/dedupe-assets.sh`), and `build-phone-rootfs-inside-fedora.sh` installs the wallpaper only to `/usr/share/nuxel/nuxel-background.png`, never to the PWA's own `assets/`. `css/style.css:60` references `../assets/nuxel-background.png` | handset `curl` → `404 text/html 460`; `find /usr/share/nuxel/pwa/nuxel-home/assets` → only the MP4; `.gitignore:119` |
| R3 | touch does not control the launcher | **phoc has zero `/dev/input/*` fds.** It is started with `WLR_BACKENDS=headless`, which makes wlroots skip the libinput backend entirely; adding `libinput` then fails because wlroots cannot start a backend *session* (`failed to start a session`) — libseat on Fedora 43 has only `logind`/`seatd`/`noop` (no `builtin`), there is no logind session, and no seatd daemon. So the compositor never sees a finger even though sec_ts, evdev and `nuxel-touch-arm` all work | `ls -l /proc/5354/fd` → only eventfd/eventpoll; throwaway phoc runs: `failed to start a session / failed to add backend 'libinput'`; `python3` scan of `libseat.so.1` → `['logind','seatd','noop']`; sec_ts IRQ 57 and `TOUCH_POINT` in the state file |
| R4 | second boot animation on the phone | `pwa/nuxel-home/index.html` carries `<div id="boot-splash">` + a fullscreen `autoplay loop` `<video>` at `z-index:99999`, faded only after ~3 s of playback or a 12 s timeout (`js/app.js`). The OS already played the authoritative animation from the initramfs, so this is a redundant second animation *and* a `pointer-events:auto` overlay above the launcher | `index.html`, `css/style.css:248-273`, `js/app.js _finishBootSplash()`; `NUXEL_HOME_MEDIA enable_media=0` |
| R5 | app activation unproven | The VM runs `nuxel-bridge`, `nuxel-http-bridge` (`127.0.0.1:8080`, dev mode, per-session tokens, CORS `http://127.0.0.1:8000`) and `nuxel-notifications`/`nuxel-portal`; the handset image has **none of them installed**, and `nuxel-pwa-host`'s permission handler allowed *every* permission request from *any* page | VM `systemctl list-units`/`ss -lntp`; `services/nuxel-bridge/*`; `tools/s10plus/a29/nuxel-pwa-host.c on_permission()` |
| R6 | display reset churn | the A29 bridge re-issues `FBIOPUT_VSCREENINFO` + `FBIOPAN_DISPLAY` **every second** in its reporting block | `tools/s10plus/a29/nuxel-wl-fb.c` steady loop |

## 3. Deliberately preserved

* The A27 framebuffer UI remains installed and reachable as
  `nuxel-fallback.service`; it is simply not the panel owner while the launcher is
  present (`ConditionPathExists=!/usr/lib/nuxel/nuxel-wl-fb`).
* `nuxel-touch-arm` arms the controller **once** (tsp `module_off_master` → `fb0`
  blank 1→0 → hold a reader fd) and then only reads: no repeated blanking
  (mission 11.4).
* No kernel, BOOT or initramfs change is needed for any of R1–R6; all six are
  userspace.
