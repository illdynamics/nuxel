# Native S5000AP voice call protocol and audio-path contract

Round 07, voice gate. Matches vendor `libsec-ril.so` (SHA-256
`b02bd095ae44a991b3cb676e584b3209a947160c22e678578f8b0c877e282cb3`), baseband
G975FXXSEFUJ2. Call control is source-validated and host-tested; **two-way
audio and physical call placement are not yet verified** and remain owner-gated.

## Command family

`IPC41_MAIN_CALL = 2` (CALL_CMD), recovered from the vendor dynamic symbol
table. Genuine command IDs only — nothing guessed from other Samsung
generations. All serializers are covered by golden vectors generated by
isolated vendor execution (`scripts/recover_vendor_vectors.py`).

| Operation | sub / AP type | Wire bytes (after 7-byte FMT header) |
|---|---|---|
| Originate (dial) | 1 / EXEC 1 | 92 B: `type` u16 LE (0x0100 normal voice), `clir` u8 (0 default), `numlen` u8, `ton_npi` u8 (0x11 int'l, 0x21 national), digits, zero padding |
| Answer | 4 / EXEC 1 | 0 B |
| Release (hangup) | 3 / EXEC 1 | 0 B |
| Get call list | 6 / GET 2 | 0 B |
| Voice registration | 8/5 GET (NET family) | 2 B: `0xff 0x02` (domain/async filter) |

Golden wire (verbatim): dial international `63 00 .. 02 01 01 ..ton 0x11 ..`;
answer `07 00 00 00 02 04 01`; release `07 00 00 00 02 03 01`; list
`07 00 00 00 02 06 02`; voice registration `09 00 00 00 08 05 02 ff 02`.

## Fail-closed parsing (`fmt_call.c`)

- `fmt_call_dial` accepts only digits with an optional leading `+`; rejects
  empty, over-length (`>= 83`), or non-digit input; no emergency or
  supplementary-service encoding is produced.
- `fmt_call_list` requires a self-consistent count, per-entry 8-byte fixed
  header + digit run, call type exactly `0x100` (normal CS voice), direction
  1/2, state 1..6, multiparty 0/1, unique call ids, and exact end-of-payload.
  Any deviation returns false (no partial/noisy list exposure).
- `fmt_call_status` requires exactly 6 bytes.
- Call state names: 1 active, 2 held, 3 dialing, 4 alerting, 5 incoming,
  6 waiting, else "unknown".

## Call FSM (`call_service.c`)

- Single outstanding command; 30 s deadline; 1 s list re-query while any call/
  dial/answer is in flight, otherwise 60 s.
- Offline CP transition clears pending state, marks the result `-2`, and emits
  an "unknown" state for every previously-listed call — no stale active call is
  preserved through a modem loss.
- Incoming detected when any listed call is state 5/6; answer is refused unless
  such a call exists.
- `hangup` supersedes setup on explicit user cancel.

## Audio path — NOT implemented (truthful)

`GetVoiceStatus` reports `audio_route=unconfigured` and `ims=unimplemented`.
No Exynos ABOX ALSA/UCM `VoiceCall` verb, no PipeWire call-stream routing, and
no SCO/Bluetooth headset path has been wired or validated on S5000AP. Call
control is independent of microphone/recording permission, and the lack of an
audio route is reported rather than faked. Work remains:

1. ABOX codec `VoiceCall` UCM verb + mixer route (earpiece/speaker).
2. PipeWire call node route to that verb.
3. SCO/HFP only if a proven Bluetooth audio path lands.
4. Radio-loss teardown: close the call stream on CP offline (FSM already emits
   state change; audio teardown is unexercised).

## Negative tests (host-only for now)

No-SIM / no-service / airplane mode paths are host-fenced: with CP not online,
`call_service_tick` refuses dial, rejects answer (no incoming in list), and
emits `unknown` for prior calls. Physical airplane/SIM-absent tests require the
device and are owner-gated.
