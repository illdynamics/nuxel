# NUXEL PWNAGE-101000
## External HDMI Colour Correction, Automatic Orientation & Hot-Plug Reconnection Recovery

**Device:** Samsung Galaxy S10+ SM-G975F (`beyond2lte`)  
**SoC:** Exynos 9820  
**Project:** Nuxel  
**Repository:** `~/x/nuxel`  
**Previous milestone:** PWNAGE-100000 — physical HDMI output achieved  
**Full specification:** `full-pwnage-101000.md`

---

## Mission

Fix three related defects in Nuxel's now-working USB-C-to-HDMI external display implementation:

1. **Incorrect colour rendering:** The external display currently shows a severe red/orange colour cast.
2. **Orientation and landscape handling:** External output must correctly respect the phone's portrait/landscape rotation and display orientation changes without sideways, stretched, cropped or incorrectly scaled output.
3. **Disconnect/reconnect recovery:** After disconnecting and reconnecting the USB-C-to-HDMI adapter, the external display no longer comes back. Nuxel must reliably detect the connection again, re-establish the output pipeline and restore the display without requiring a reboot or manual service intervention.

These are all required parts of this task. Do not fix one while ignoring the other two.

## Important physical evidence

The user has supplied a photograph showing the Nuxel desktop and a live terminal window visibly rendered on the external TV through the S10+ USB-C-to-HDMI connection.

This confirms that external picture output has worked on the actual phone.

The original image exhibits a strong red/orange cast. The connection has also been reported to disappear after unplugging and reconnecting the adapter.

**Preserve the working HDMI output implementation. Do not regress the physical connection while fixing the remaining problems.**

## Required execution

Read `full-pwnage-101000.md` completely and execute it.

Start with the actual live device state. Inspect the previous PWNAGE-99000 and PWNAGE-100000 implementation and reports, then inspect the currently running services and external display pipeline.

### A. Colour correction

Identify the precise source of the red/orange tint.

Inspect the original Wayland pixel format, external framebuffer bitfields, conversion logic, stride, endianness, alpha handling and any subsequent colour transformations.

Compare actual source pixels with the bytes written to the external framebuffer.

Implement the correct conversion. Do not blindly swap RGB/BGR or compensate with arbitrary gamma, tint or filters.

### B. Orientation and automatic landscape handling

Make Nuxel's external display behave correctly as the phone rotates.

Requirements:

- Detect actual phone orientation using the existing Nuxel/compositor/sensor orientation pipeline.
- Respect portrait and landscape transitions.
- Correctly update mirrored content when the phone rotates.
- Make landscape applications and the landscape desktop display correctly.
- Avoid sideways, stretched, cropped, squashed or incorrectly letterboxed output.
- Preserve correct scaling and aspect ratio.
- Coordinate compositor orientation, screencopy dimensions, external buffer dimensions, transform and framebuffer output.
- Handle rotation while HDMI remains connected.
- Handle HDMI reconnect while the phone is already in landscape.
- Keep the physical TV output mode appropriate for the actual TV. Do not blindly rotate the HDMI signal timings by 90 degrees just because the phone rotates.
- Keep manual external rotation available where appropriate, but make automatic phone orientation work without requiring manual settings changes.

Mirror mode should follow the actual phone UI orientation while presenting a correctly composed picture on the normally landscape TV. Do not simply rotate the entire TV image sideways when the phone changes orientation.

### C. Reliable USB-C-to-HDMI reconnection

Fix the failure where the external display disappears after disconnecting and reconnecting the adapter.

Implement a proper event-driven detection and recovery lifecycle covering:

- Adapter disconnect.
- Adapter reconnect.
- Type-C partner removal and reappearance.
- USB-PD renegotiation.
- DP Alt Mode rediscovery and re-entry where needed.
- DP mux and PHY reinitialisation through the legitimate driver path.
- HPD and AUX recovery.
- EDID and mode rediscovery.
- External output/framebuffer re-enumeration.
- External bridge restart or reinitialisation where necessary.
- Display manager state recovery.
- Mirror mode restoration.
- Rotation state restoration.
- Audio endpoint removal and recreation.

Do not merely restart the whole phone or tell the user to restart services.

Implement bounded recovery, proper state invalidation and safe reinitialisation without disturbing the internal AMOLED display.

### Mandatory verification

Physically verify all three areas:

1. RGB colour bars and neutral greyscale on the TV.
2. Portrait → landscape → portrait transitions with HDMI connected.
3. Multiple physical USB-C-to-HDMI disconnect/reconnect cycles, including reconnect while the phone is in landscape.

After every reconnect, the actual external picture must return automatically.

The normal Nuxel desktop must display correctly with accurate colours and orientation.

### Safety and architecture

- Do not break the working DP Alt Mode path.
- Do not reflash kernel/DTB/firmware for a userspace defect.
- Do not add a second `/dev/fb0` writer.
- Do not replace Phoc or the existing compositor.
- Do not force software rendering.
- Do not fake HPD, EDID, display readiness or HDMI audio.
- Do not blindly restart unrelated services.
- Preserve internal AMOLED output.
- Use the existing deployment system under `./scripts`, inspecting it before use.
- Back up changed components and provide rollback.
- Preserve unrelated user changes.
