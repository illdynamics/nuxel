Security

Screen lock method

The credential verifier is owned by the root bridge (scrypt, constant-time comparison). A JavaScript overlay cannot unlock the session by itself. The current mode is applied immediately and the session locks.

Checking lock policy…

PIN code

This PIN is the fallback for the fingerprint and, in PIN mode, the unlock code. Enter it twice; nothing is stored unless both entries match.

—

Pattern lock

Draw the pattern, then draw the same pattern again. It is only enabled after two identical entries, so a mis-drawn pattern can never dead-lock the phone. The 3×3 matrix uses the same penguin dots as the lockscreen.

Draw a pattern (at least 4 dots).

Unlock after the swipe

The lockhead is always the first surface. Swipe it up, then unlock: directly (Swipe), with the PIN, with the pattern (PIN button below it), or with fingerprint + PIN fallback. Swipe needs no code; the others need their credential to be set above.

—

Failed attempts

Unlimited allows any number of mistakes: the correct code is always accepted and the phone can never be locked out. Limited re-enables the growing delay after repeated failures.

—

Fingerprint unlock

The fingerprint record is stored securely in the Nuxel Vault, so the Vault must be set up and unlocked first. The scanner needs the OEM trusted application; when it is missing the scanner is shown as unavailable and the PIN fallback always works.

On this Galaxy S10+ image the QBT2000 ultrasonic sensor is bound to the Samsung TEE (TrustZone): the kernel exposes only diagnostic sysfs, no frame or match path, and the vendor HAL that talks to the secure matcher is not part of a Nuxel rootfs. Enrolling here would therefore record an enrollment that could never be matched — so setup stays disabled and the PIN remains the unlock method until a TEE/HAL provider exists.

USB network

USB networking & tethering

USB networking gives the attached computer a local point-to-point link (phone 10.15.19.1, host 10.15.19.2) for USB SSH and file transfer. It does not share Internet. The CDC‑ACM serial recovery console is kept in every mode.

Checking USB networking…

USB Internet tethering

Grants the attached computer Internet access through one selected upstream, using narrowly scoped forwarding + NAT. Off by default. Refused while a VPN kill switch is armed unless the VPN interface itself is selected.

“Share Internet with attached computer” enables the USB network composition and starts the scoped forwarding/NAT in one explicit owner action. The host must be configured 10.15.19.2/24 (gateway 10.15.19.1) and prove Internet itself; the phone shows “verified” only after that evidence arrives.
