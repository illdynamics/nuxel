- Map exact first-failure chain: `CP power/boot status → signed firmware authenticated/accepted → boot confirmation → SHMEM/SBD IPC live → RFS service valid → SIPC5 requests answered → SIM state → registration → PDP bearer → rmnet IP address/routing/DNS → real Internet`. For each stage, define source of truth, read-only observable, allowable operation, expected result, timeout and rollback. Distinguish host transport ready from CP ONLINE, SIM READY, registered, attach and bearer active. Redact IMSI, ICCID, IMEI, phone number, PIN/PUK, carrier private APN and user messages in all logs/reports.
- Confirm radio firmware and stock CP image build metadata via owner-provided **non-sensitive metadata**; no raw dumps of modem/EFS, NV, secure calibration or other users' SIM material. Document what is missing rather than fetching or copying phone-specific secrets.

## Phase 1 — exact secure CP bootstrap, then native loader only if required

- Establish the exact matching Samsung `cbd` transaction from permitted source or owner's authorized, safe trace: order and semantics of CP status/reset/power-on, secure boot requests, firmware container sections, start/download/confirmation, memory mapping/alignment and bounds, startup response and timeout. Derive ioctl values and struct layouts from pinned `modem_prj.h` and the actual ARM64 kernel; no guessed offsets or commands. Never modify signed image, defeat secure boot/TEE, alter NV/calibration/IMEI or try engineering samples from another device. Default service mode is **dry run** with a fully logged, redacted stage plan; protect all firmware and radio operations behind a narrow authorized service.
- Write `nuxel-cpbootd` only if no matching existing `cbd` can be safely reused. Verify model/build/signature metadata and SHA-256 of every payload, use bounded chunk/length/checks, one exclusive owner for `/dev/umts_boot0`, all error returns handled, no automatic boot loops, no partition writes and no RF transmit until explicit legitimate modem operation. Verify the **actual MODEM_STATUS state transition** and corresponding kernel boot confirms. If secure stage rejects firmware, stop with precise vendor requirement. No 'force modem on' infinite loop.

## Phase 2 — RFS and SIPC5, narrowly and robustly

- Study and implement only the S10/S5000AP-specific documented SIPC5 control framing (start/frame header, channel ID, length, sequence, event class, fragment alignment, endian and unsolicited responses), using the pinned source and verified owner-approved example traffic. Parser must enforce strict bounded allocations, endianness, length consistency, timeouts, replay/correlation, CRC if relevant, fragmentation caps and cancellation; fuzz malformed packet tests and concurrent request races. Single owner of `/dev/umts_ipc*` read loop; no `cat` of binary data that might disclose secrets. Requests for SIM readiness, registration, signal, PDP context and SMS must have individual, explicit supported/unsupported methods.
- `/dev/umts_rfs0` may be needed by CP, but it is **NOT** permission for arbitrary host filesystem or NV writes. Derive RFS protocol and restrict host paths to validated allowlists; reject traversal, symlinks, secrets, EFS/EFSG/SEC_EFS and changes to IMEI/calibration/key stores. If CP absolutely requires forbidden proprietary RFS/NV material, document the barrier and stop—do not bypass protection.
- Build `nuxel-radiod` (or a proven reused vendor RIL bridge) with versioned authenticated D-Bus endpoints: CP state, radio enabled, SIM present/absent/PIN-required, signal and registration, operator and technology, data bearer create/delete, packet counters, SMS capability and voice capability. Never expose raw SIPC/AT modem control to arbitrary PWAs or permit anonymous APN changes. Require user action for SIM PIN and sensitive operations. Test crash/restart, CP reset, no SIM, wrong SIM PIN path and no-network mode without exposing identifiers.

## Phase 3 — genuine ModemManager + NetworkManager cellular data

- Only once CP is **actually online** and SIPC5 responds, write or adapt an exact-version ModemManager plugin/backend so `mmcli -L` sees the real modem with supported 3GPP/SIM/bearer APIs. ModemManager must genuinely load an AArch64 ELF with resolved dependencies and match CP device ports/udev; a filename or manually created D-Bus object doesn't count. Map each capability separately, with `supported=false` for unimplemented ones. Avoid a fake broad "modem present => voice, SMS, data all work" rule.
- With an owner-authorized active SIM/plan/APN, demonstrate SIM ready, operator registration and attach, a real PDP/bearer activated, correct `rmnet` mapping, assigned IP/IPv6 (if supported), routes and DNS, HTTPS traffic with **Wi-Fi disabled** while USB/serial remains available for diagnosis. Verify the actual traffic increments rmnet counters and is billed/carried over the mobile link, not over cached Wi-Fi/USB NAT. Check reconnection/airplane mode, intermittent signal, SIM removal if physically supported, reboot, thermal/battery cost and clean teardown. Do not trigger carrier registration commands blindly without permission.

## Phase 4 — SMS, voice, audio and IMS are separate gates

- SMS PASS requires two real owner-approved numbers and send/receive evidence with sensitive content redacted, correct storage/encoding and no mock messages masquerading as sent. Existing `nuxel-messages` local/mock should remain visibly labelled offline if SMS isn't implemented.
- Ordinary voice PASS requires explicit opt-in call to a **consenting non-emergency** number, verified two-way audio through the existing audio routing stack, reliable ring/answer/end, microphone permission and graceful radio loss. A dialer button appearing or an API method being callable is not proof.
- IMS/VoLTE PASS requires correct carrier-supported provisioned stack, regulatory compliance and validated normal user call; do not imply IMS works merely because LTE data works. Report `UNSUPPORTED_IMS` if independent carrier/vendor components are missing. SIM contacts sync is not a real SIM phonebook until verified from actual modem protocol.
- Nuxel Settings, Quick Settings, status bar, Dialer, Contacts and Messages must reflect *each* real capability and current state, with safe user confirmation for radio on/off and airplane mode. Require a successful negative no-SIM test with no false signal bars, operator, SMS or data.

## Measured exit criteria

**Minimum full mobile-data PASS**: CP firmware boot and secure acceptance; IPC ready; real SIM state; network registered; ModemManager enumerates a genuinely probed modem; bearer activation; `rmnet` traffic, valid IP + DNS + working HTTPS with Wi-Fi off; stable reconnect and reboot, clean radio-off; logs redacted. **Additional PASS** for SMS, ordinary voice and IMS only after their own physical tests. Run crash recovery, airplane-mode toggle, boot with no SIM, failed bearer, two cold boots, extended idle and thermal regression. Provide a segmented `reports/S5000AP-RADIO-ENDGAME.md` with exact successful layer and any unimplemented capability, reproducible `nuxel-cpbootd`/`nuxel-radiod` changes, pinned UAPI test harness, ModemManager plugin proof, systemd/udev authorization, install manifest and A-only rollback.

If matching secure CP firmware/`cbd`/signed boot service or carrier provisioning is unavailable, do **not** silently reclassify the modem as solved. Deliver the real host-side tooling/tests/source you can complete, and mark the exact first blocked protocol stage and the minimal lawful owner/OEM input necessary to proceed.
