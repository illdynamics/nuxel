# Nuxel SM-G975F: six remaining feature tracks — source and research audit

**Audit date:** 2026-11-16. **Subject:** supplied `nuxel-main (1).zip`, not an assumed Git working tree. **Scope:** archive/source/recorded evidence and public upstream projects. **No phone connection or live hardware operation was performed in this audit.** Owner-specific IP addresses, credentials, serials, and private data intentionally omitted.

**Archive SHA-256:** `1272b6acc4e4fe975c3d1d9682c80a887043e5fc3e899350e540bb0db395895d`. Actual ZIP size **477,112,030 bytes (~455 MiB)**; combined compressed member payloads **471,397,522 bytes**, uncompressed member sizes **1,039,396,300 bytes (~991 MiB)**; 21,469 ZIP entries, of which 19,179 are files. All entries were extracted locally for inspection. The archive is a working-tree snapshot; do not infer the phone's latest state or claim full Git ancestry from the ZIP.

## Highest-consequence findings

1. **The target is A-only.** `device/s10plus/deviceinfo` says Samsung S10+ SM-G975F `beyond2lte`, Exynos9820, downstream 4.14.253, Android v1 boot image, base `0x10000000`, and `deviceinfo_boot_slots="none"`. The confirmed routes are TWRP ADB + checked `dd` or Heimdall BOOT/SYSTEM. There is **no inactive A/B slot** for safety. Some older generic reports incorrectly recommend switching slots; **do not use that advice**. Confirm the live partition names, fstab and PIT before any write. Do not treat TWRP availability as a boot guarantee.
2. **The six tasks cover five underlying physical subsystems.** Accelerometer/gyro streaming (prompt 3) and automatic rotation (prompt 4) share the BCM47752 SSP/BBD prerequisite, but have distinct physical acceptance tests and service/UI work. If prompt 3 fails at MCU patch/streaming, prompt 4 cannot truthfully pass. NFC is independent; camera, fingerprint and radio are separate high-complexity tracks.
3. **NFC `/dev/nfc0` is not the standard Linux success criterion.** The upstream Linux NFC userspace ABI is generic netlink for control and `PF_NFC` for data; `/sys/class/nfc/nfc0` is meaningful, but `/dev/nfc0` need not exist. `reports/final-summary.md` from Nov 15 specifically observed class NFC `nfc0` while missing `/dev/nfc0`. `final-state-components.md` from Nov 16 describes fallback to `/dev/sec-nfc` and failed NCI reset/clock. Resolve the current boot's active driver and `NFC_CMD_GET_DEVICE/START_POLL` behavior, not a fabricated char node. The NFC reference clock is reported at 0 Hz in `reports/NFC-STATUS-20261112.md`; vendor bootloader replies are real, NCI `CORE_RESET` response and actual tag I/O are not. Never confuse the separate later S3NRN4V controller with this S3NRN82.
4. **NFC has previously bootlooped the entire phone.** `evidence/live-20261114/BOOTLOOP-ROOT-CAUSE.md` records a kernel panic in `sha1_ce_transform` from the NFC firmware download, with three identical TWRP returns. `kernel/s10plus/patches/0023-nuxel-nfc-fw-sha1-stack-safe.patch` is present, but source presence is not proof it is in the current boot. Required gate: no automatic firmware flash, bounded hashing, stack/SIMD audit, and reproducible rescue boot rollback.
5. **The camera's 'firmware absent' claim is stale relative to the ZIP.** `reports/REPORT-CAMERA.md` says missing firmware and no real frame. But this ZIP contains substantial binary files under `firmware/s10plus/blobs/device-vendor-firmware/`: `fimc_is_fw_mcu.bin` 34,348 bytes, `fimc_is_lib.bin` 4,432,944, `fimc_is_rta.bin` 3,986,208, and five `setfile_*.bin` (roughly 2.9–4.1 MB). The latest `configs/nuxel/camera/camera.json` says the relevant per-mode sensor setfiles are **compiled into the kernel** and that the camera runtime requests `fimc_is_lib.bin`, `fimc_is_rta.bin`, and optionally the MCU firmware. It specifically rejects older placeholder names such as `s5k2l4_setfile.bin`. **`setfile_3j1.bin` and `setfile_4ha.bin` are byte-identical** (same SHA-256 `dc352608088d409dfc9faf3c5475d045220f5316f49cee4d6619dd98ce076876`); this might be intentional or a wrong copy, and requires provenance/ABI review before use. Distinguish present-in-ZIP, installed-on-phone, requested-by-running-kernel, successfully loaded, and physical frames. Do not publish proprietary files.
6. **A camera probe client already exists, not just a UI.** `tools/s10plus/fimc-capture/nuxel-fimc-capture.c` implements V4L2 **multi-planar** format/buffer/stream operations and a `--probe-only` mode, addressing the `ENOTTY` from earlier single-planar attempts. `kernel/s10plus/patches/0022-nuxel-fimc-is-linux-firmware-paths.patch` adds Linux search paths, and `shell/nuxel-camera-portal/` plus `shell/nuxel-camera-native/` already exist. Start by verifying the existing capture client, driver ABI, runtime and real frames; do not propose writing a whole libcamera pipeline before testing it. Generic upstream libcamera has no listed Exynos9820/FIMC-IS2 pipeline support.
7. **Fingerprint is a secure-world dependency.** `diagnostics/pwnage-91000/hardware/fingerprint-live.txt` captures `/dev/qbt2000_fd`, `/dev/qbt2000_ipc` root-only and QBT2000 sysfs. `services/nuxel-bridge/src/fingerprint_provider.py` correctly returns `BLOCKED_SECURE_PROVIDER`, `secure_tee=false`, with PIN fallback. `packs/finger/full-pwnage-finger.md` references a separate `startup.tzar`/`libtzld.so` secure-world hash-integrity issue and a possible missing owner authorization gate for mutating fingerprint verbs. Verify integrity and authorization first. Installing `fprintd` does not create TEE support and never warrants enabling fingerprint unlock. No raw templates/images should leave secure hardware.
8. **SSP work is farther along than 'sensor node exists'.** `reports/SSP-CONTINUATION-20261113-2130.md` records native `tools/s10plus/ssp-native/nuxel_bbd_download.c`, UART/SPI/BBD framing, CRC, RPC ids, and the embedded `/dev/bbd_patch` payload: ASIC `0x004775B0`, blob length 438,895 bytes, device `/dev/bbd_patch` about 897,113 bytes. Kernel fixes in patch `0020-nuxel-ssp-hub-power-and-pm.patch` correct regulator acquisition and resume initialization. BUT after runtime suspension SPI MISO read `0xFF`, zero samples persist, and GPIO `gpg0-2`/145 toggling high has **rebooted the phone twice**; never repeat that unguarded experiment. Matching vendor `lhd` and Bionic sensor libraries have been extracted to `packs/sensors/acquired/` but cannot simply execute under glibc. Prefer a legally authorized matching isolated Android runtime or finish the existing native patch loader; avoid substituting BCM47765 firmware.
9. **Manual rotation is already reported working.** The same SSP continuation shows `portrait=normal`, `landscape=270`, `reverse_portrait=180`, `reverse_landscape=90` live compositor transforms after `nuxel-orientationd` CLI correction. The seven-mode policy must be preserved, with `auto_state=blocked_sensor_unavailable` until verified real accelerometer samples. `nuxel-ssp-bridge` is masked because it cannot conjure samples. Auto-rotate work should prioritize gravity vector, coordinate transform, hysteresis, IIO/bridge, and actual Wayland application after prompt 3 delivers motion.
10. **Modem kernel driver is not inherently missing.** `docs/Samsung S5000AP - Exynos 9820 Native Linux Modem Bring-up for Nuxel.md` and `packs/mobile/docs/ARCHITECTURE-AND-GAPS.md` identify the pinned `modem_v1`, `s5000ap`, SHMEM/SBD/SIPC5 and historical `/dev/umts_*` + `rmnet0..7` registration. Nov 15 `reports/final-summary.md` says `s5000ap` is OFFLINE, `mmcli -L` no modems, `rmnet0` DOWN. This is likely an **OEM CP boot / RFS / protocol integration** gap before ModemManager, not a reason to rewrite the kernel driver. Stage-zero read-only tool exists at `packs/mobile/tools/s5000ap-status.c`. Never confuse an offline rmnet interface with no kernel data interface. The ZIP contains **zero-byte placeholder plugin fixtures**: not loadable Shannon plugins. Do not touch EFS/IMEI/NV/calibration/modem partitions or request SIM secrets.
11. **Diagnostics and historical reports disagree because they're from different boots and changing source.** Use `PROVED_LIVE`, `HISTORICAL_LIVE`, `PRESENT_IN_REPO`, `PROVED_UPSTREAM`, `INFERRED`, `UNKNOWN` for each claim, always with time, running kernel, SHA and source. A source edit, binary in ZIP, stopped daemon, successful host test, or created device node never proves real hardware behavior.

## Execution order and dependency model

**Recommended:** (1) SSP sensor physical streaming → (2) auto-rotation integration; in parallel, NFC and camera; then fingerprint secure-provider research, and S5000AP CP userspace boot/RIL. Follow an evidence gate, not a fixed calendar. NFC and sensor-hub experiments are boot/kernel-risky; use one at a time with known-good BOOT rollback. Camera can attempt read-only probe and userland first. Fingerprint and cellular are artifacts-dependent and may not be achievable without compatible, lawfully acquired OEM components.

## Cross-cutting live/flash guardrails

- All kernel flashes require identifying the physical target, obtaining the existing **known-good** boot image and partition table first, validating signatures/size/hash/build/DT/ramdisk alignment, selecting exactly BOOT as intended, and testing the recovery path **before** experimentation. No generic A/B slot commands. Use the repo's `boot/s10plus/*`, `scripts/nuxel-deploy-live.py` only after reading them in the actual worktree. Never hard-code physical disk path or a remembered IP without discovery.
- Prioritize reversible userspace changes and read-only probes; use a dedicated out-of-band USB serial/ECM or TWRP ADB path if a test could disable Wi-Fi or cause a reboot. Never write unrelated partitions or secrets; no infinite restart/flash loops; no forged test outputs; no hidden camera/microphone capture; no counterfeit radio registration.
- Preserve OEM integrity and vendor licensing: firmware/TA/CP packages must match the model/build and remain local if redistribution is prohibited. Do not bypass TEE signatures, tamper with biometric templates or IMEI, or transmit cellular/NFC payment traffic in tests. A physical sensor/preview/tag/SIM test needs explicit owner participation and genuine test media.
- No honest engineering agent can guarantee 100% feature completion when silicon, secure signing, proprietary documentation, carrier support, or physical hardware are outside its control. Demand a tested fix when technically possible; otherwise report exact minimal unblocking artifact and evidence, never fake a PASS.
